# 这工具管什么

你在正文里写「主对照有 16 个实例」。工具顺着这一行往下查：有没有标 `\fact{A1}`，账本里 A1 是不是 16，那份原始产物还在不在、哈希对不对、有没有人签过字。

引用同理。`\citep{nosek2018}` 去 `refs.bib` 找条目，看有没有 DOI 或者 arXiv 号。

改写的时候，它把改前改后两个目录摆在一起逐项比：`\fact` 标记、数字、引用、公式、表格行、交叉引用。变了就报红，告诉你第几行。

就这些。

## 它不管的

结论对不对，不管。

写得好不好读，不管。

审稿人喜不喜欢，不管。

抄没抄别人，不管。

## 别人问起来

> 它保证账、材料、正文三者对得上，材料没被偷偷换过。论文结论对不对，它不知道。

## 几个数字别读错

审计绿，意思是 0 红 1 黄，两个数字和一条引用都对上了账。不是「论文没问题」。

盲评 69%，意思是某个问法下某群评委的选择。换个问法，结论会翻。

黄牌从 42 降到 17，意思是触发项少了。不是文章好了。

## 为什么这么写

同一批改写稿，换个问法，结论会翻。

- 问「哪版更像论文」，多数人选旧版；
- 限定体裁、清楚和专业分开打分，新版赢 71.7%；
- 换模型、把标签对调，47.5%。

文本没改。

三个评委的一致性一度算到 1.000，看着可靠。标签换位再问，胜率掉 16.8 个百分点。

一致，不等于判得对。

## 安全边界

只对**你自己信任的项目**跑 `build` / `audit --build`：`project.build` 是项目声明里的 shell 命令，工具会照原样执行。`audit` 本身不编译、不执行它；`--build` 才会。

`audit --resolve` 会把引用里的 arXiv / DOI 编号发给对应的解析服务；不发正文，也不发你的本地路径。

## 自己验

```bash
python3 -m factscribe audit <项目>                    # 账和正文对不对得上
python3 -m factscribe protect --before 旧 --after 新   # 改写有没有动硬东西
python3 -m factscribe tide --before 旧 --after 新      # 这次改动能不能闭合
```

设计规范在 `docs/design/`，已知缺口在 `docs/release/KNOWN-GAPS.md`。
