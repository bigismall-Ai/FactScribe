# FactScribe 第 2 轮圆桌（R2）

> 席位：外部红队（mcode CLI，18 条）／蓝队／主持（编排）
> 靶子：`SPEC-V2.1.md` → 产出 `SPEC-V2.2.md`（1617 行）

## 一、这一轮红队打中了什么

**一句话**：v2.1 保证的是「**被扫描到的 token** 都被账授权」，不是「**被渲染出的数字** 都被账授权」。两者之间差一次宏展开。

三条具体逃逸路径（都有可复制反例）：

| 路径 | 例子 | v2.1 为什么漏 |
|---|---|---|
| 宏体在 preamble | `\newcommand{\bad}{1/16}`，正文 `\bad` | 按「结论文本」定义，preamble 不在扫描面 |
| token 拼接 | `9` ＋ `1.4` 渲染成 `91.4` | `91.4` 从来不是任何 token |
| 计算生成 | `\numexpr`、`\setcounter`、`\the\value` | 派生数不是 token |

另两问：**句级绑定**在中文无空格、一句多 fact 时没有定义；**run record** 若由同一 agent 写，等于同源自证。

## 二、蓝队裁决与 v2.2 的四个新判据

18 条：**采纳 11 ／部分 7 ／纯驳回 0**（7 条部分采纳里另有 8 个子条款驳回，逐条写进 §1.4「接受风险＋缓解」）。

| # | 判据 | 要点 |
|---|---|---|
| **R-01A 渲染可归责** | 扫描面＝闭包内**全部文本**（含 preamble、`main.tex`、`.md/.txt`）；**算术命令族一律红**（`\numexpr`/`\setcounter`/`\the\value`/`\pgfmathparse`…）；**数字不许贴宏**（`\foo9`、`9\macro1`、贴空组、贴闭合组）；`\ref` 单列放行，写明是**设计取舍** |
| **R-02 句级 BU** | 全局文本流切句（**不按文件边界切**）；逗号不切段、标记右绑；同组多 fact 按出现顺序一一归属，**A/B 对调必红**；`display` 必须与 `value` **严格等价**，冲突以 value 为准判红 |
| **R-03 信任模型** | run record 写者/签名/回执角色写进规范；回执同时钉 `request + response + run_id + attempt`；**人签从"签 id"改成"签内容哈希（含 rules_sha256）"**，改内容不重签即 `APPROVAL_STALE` |
| **R-04 反滥用** | `UNVERIFIED` 独立 **exit 8**；`PASS` 只在 **L2** 出现；CI 判定式写死 `exit==0 && verdict=="PASS"`；`release` 强制 L2 ＋ **PDF 回检**（`verify-pdf` 把 PDF 里抽出的数字与 `number_ledger` 对表） |

## 三、明确驳回、写死接受风险的一条

**2-S5「证明被藏起来的 attempt 不存在」**——单侧证据无法证明全集。
处理：**驳回**，改为「per-attempt + 预注册聚合 + `ATTEMPT_COUNT_MISMATCH` + nonce」，并写进规范：**只能缓解，不能证明**。

这条和 R1 的"信任根是人签"是同一条边界的两面——**工具能做的上限是"账、据、文三者自洽且未被偷改"**。

## 五、R3 请重点打这三点

1. **`verify-pdf` 的信任链**：PDF 由同一次构建产生，agent 能不能生成一个"数字被抹掉"的 PDF 来过检？回检的是 PDF 文本层还是渲染像素？
2. **人签的粒度**：签 `rules_sha256` 解决了"改规则不重签"，但**谁**签？如果 agent 能调用签名接口，这套是否又回到自证？
3. **36 个夹具会不会变成"应试"**：我们按红队的攻击写夹具，通过率高只能证明"打得过的都防住了"，不能证明"没打过的也防得住"——需要一轮**不告知夹具**的盲测。
