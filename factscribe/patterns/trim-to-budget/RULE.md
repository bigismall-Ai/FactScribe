# trim-to-budget｜压到预算内：先删重复，再删举例，最后合并

## 治的判据

- 错误码：SECTION_LENGTH
- 现象：本节正文超出项目预算（`[budget]` 的 `default` 或
  `[budget.sections]` 覆盖值）的 120%；`style` 给的读数是
  「本节 N 词 / 预算 M 词（超出 X%）」。
- 只治「写多了」这一件事：不碰事实、数字、引用、结构与论证方向。

## 必做

按这个顺序压，一步做完再进下一步：

1. **先删重复引用的数字**：同一个数字在同一节出现多次时，只留论证真正
   需要的那一处（通常是第一次），其余改成「该数」「上表读数」这类回指；
   数字本身与 `\fact{id}` 绑定一处都不许改。
2. **再删举例**：例子是支撑，不是论点。多个例子讲同一件事时只留最有力的
   一个；每个论点至少留一条证据，不留孤立的断言。
3. **再合并同义句**：两句说同一件事时合成一句，保留限定条件与数字；
   合并后仍是一句完整的话，不是把两句用逗号粘起来。
4. **压完再数**：用 `style` 的读数复核，降到预算的 120% 以内即闭合
   （与 `SECTION_LENGTH` 同一口径：英文按词、中文按汉字）。

## 禁做（含反例）

- 禁删论点：一节里有几个论点，压完还是几个。反例：把「机制改动的收益大于
  提示词改动」整段删掉 → 只剩方法描述。
- 禁删每个论点的最后一条证据：删到只剩断言就是换了个错法。
  反例：`机制组读数变化更大（十六次运行）` → `机制组读数变化更大`。
- 禁把句子改短来凑数：拆句、断句、删虚词但词数不降，是换法子过检查。
  反例：把一段拆成三行短句、词数没降
  （`模型在十六次运行里都保持稳定，只在措辞层面有变化。` →
  `模型在十六次运行里。都保持稳定。只在措辞层面有变化。`——三行短句，
  词数没降，句子还残了）。
- 禁改数字、`\fact{id}`、`\cite`、公式、表格行与 `\label`／`\ref` 的 key。
- 禁整段删除、禁把一段拆成一串残句、禁把解释搬到别的节。

## 改写示例（旧 → 新）

| 旧 | 新 | 说明 |
|---|---|---|
| 一段 180 词：论点 ＋ 同一数字出现三次 ＋ 两个同义例子。 | 一段 120 词：论点不变、证据保留、该数字只留一处。 | 论点与证据都在，删的是重复与冗余例子 |
| `我们把结果重复列了三次：53 个样本，共 53 个样本，样本量 53。` | `样本量为 53\fact{B1}。` | 重复引用的数字只留一处 |

旧 → 新只压篇幅，不改论证：论点、每条论点的最后一条证据、数字与引用都
原样保留。

正例：一段 180 词压到 120 词，论点与证据都在。

## 验收命令

```bash
env PYTHONPATH=src python3 -m factscribe prescribe trim-to-budget --json
```

改完把该节换进项目后再复核（占位符由人替换）：

```bash
env PYTHONPATH=src python3 -m factscribe style <项目> --diff <改前目录> --json
```

`SECTION_LENGTH` 不再出现即闭合；把句子拆短、词数没降不算改完。
