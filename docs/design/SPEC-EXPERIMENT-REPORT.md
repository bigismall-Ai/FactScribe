## 0. 一句话

实验做完之后，数字进事实账（facts）、机器读数面有归一化报告（report@1），
但「把这一轮实验写成一个**人能读、能核、能追责**的文档」至今没有模板级规范
——每份报告各自发明章节，读数有没有锚、判据是不是跑前钉的、AI 干了哪些活，
全靠作者自觉。本规范补的就是这段空白：一份固定骨架的报告模板
（`experiments/report-template.md`）＋一张机械校验清单；
模板与校验器双件，不造新追踪器。

## 1. 目的与定位（三方分工）

### 1.1 目的

1. **补人读面**：给「写给人看的实验报告文档」立模板级规范——章节固定序、
   必填槽、读数四列表、AI 披露写法、弃权写法。侦察结论（工具侦察 §8）：
   **业界没有一家同时提供「人读叙事报告模板＋机器可校验数字锚」**——MLflow
   与 DVC 官方根本没有叙事层，W&B 的报告块不携带数字出处锚。本规范补这一段。
2. **数字可核**：报告里每个数字必须能机械回指到事实账条目或原始件
   （TIER soup-to-nuts 本地化，§3），并给出接 report@1 check 的映射草案（§3.2）。
3. **判据可对**：跑前钉的判据声明必须在报告里引用版本与位置；没钉的读数
   降级为「探索性」（§4）——预注册对照，与 drift-absorber 架构里
   「Spec 冻结锚」同构：判据声明之于实验＝冻结锚之于交付物。
4. **诚实可写**：判不准要能报备（区间＋不确定带，§5）、证据不足要能显式
   弃权且弃权不算失败（§7）、AI 参与要按深度分档披露且责任留在人（§6）。

### 1.2 三方分工对照（谁管什么，不重复不冲突）

| 面 | 载体 | 管什么 | 明确不管什么 |
|---|---|---|---|
| **机器读数面** | `factscribe report@1`（`SPEC-REPORT-SYNC.md`；`factscribe/report.py`：check/lock/sign、探针、digest、fact import） | 数字怎么**机械取、机械比、上锁、签收、导入事实账**；探针定位与哈希；R1–R17 校验规则 | 不管叙事怎么写、章节怎么排、AI 怎么披露、判不准怎么写 |
| **跑法纪律面** | `experiments/EXPERIMENT-MANUAL.md`（§五判读与质量读数、§六纪律红线） | **怎么开车**（sia run/填表/问询）、判读纪律（判读词跑前冻结 sha256 入档、逐数亲算、报区间＋不确定带、跨批同盘重算）、红线 | 不管报告文档长什么样、模板章节序、披露分档 |
| **人读文档面（本规范）** | 本件＋`experiments/report-template.md` | 报告作为**文档**的章节骨架、必填/选填槽、四列读数表、AI 披露分档写法、弃权合法化、机械校验清单（人读面的 grep 级判法） | 不改机读 schema、不立新跑法、不做判卷评分；判读纪律一律引用 MANUAL 原文不抄数 |

边界三句：

- 本规范**只引用不抄** report@1 的字段定义与 MANUAL 的判读口径；两面上有修订，
  本规范跟着引新版本，不另立副本数。
- 「绿＝有账、账有据、据未被改，**不是**内容为真」（report.py 追溯矩阵原文）
  ——这条边界句必须原样出现在报告模板的判定节里；报告写「判定：过线」时
  只主张「读数与锚一致且过线」，不主张「结论为真」。
- 本规范与 MANUAL 的衔接点只有一处：§5 区间与不确定带、§4 预注册对照
  在**文档面**的落法由本规范定；「跑前冻结、跑后不改」的**纪律本体**归 MANUAL。

### 1.3 非目标（写死，避免跑偏）

- **不做判分/评分**。报告模板只承载读数与锚；谁过线谁不过线由冻结判据声明
  判，判卷面零 LLM（MANUAL §五既有纪律）。
- **不改 report@1 一个字段**。本规范 v0 的校验走 grep 级；要接进
  `report check` 的部分只出**映射草案**（§3.2），实现候批另立批。
- **不强制所有报告出机读伴生件**。人读 Markdown 是 v0 主载体；
  report.toml 机读伴生件可选挂（§9.2），成对强制候裁定（开放问题 4）。
- **不覆盖替代报告与论文**。论文正文数字走既有链（report.toml → fact import
  → facts → `\fact{id}`）；本规范管的是实验报告这一层文档。
- **不做 LLM 判据**。校验清单每条都可纯机械判（§8）；沿用 SPEC.md §5
  硬性要求的精神：校验器只许纯机械、确定性、零 LLM。

## 2. 报告模板骨架（照 EQUATOR 四列表思想）

骨架思想照搬报告规范族的两件现成设计：**四列表**（CONSORT
"Section/Topic｜Item No｜Checklist item｜Reported on page No"；PRISMA
"Location where item is reported"）与**「报告位置回填」列即机械校验锚**。
模板实体落 `experiments/report-template.md`（可直接复制开写）。

### 2.1 章节固定序

固定骨架＝**报告头＋五节固定序＋选填节**。固定五节的顺序不得调换、
标题名不得改（校验器按序 grep，见 §8-1）：

```
报告头（元数据＋AI 使用声明＋签收）
§1 结论先行
§2 预注册对照
§3 读数表（四列）
§4 判不准报备
§5 追溯锚
——以下选填，置于固定五节之后、顺序不限——
§A 方法与环境        §B 轮次谱系与多轮对照   §C 计算资源
§D 失败与 null 结果   §E 偏离与变更          §F 引文与出处
```

序设计依据：结论先行是本工作区行文规矩（先说结论再讲细节）；预注册对照
紧跟结论（读者先知道「拿什么判的」再看读数，CONSORT 2025 把 Open science
前置为顶级章节同理）；读数表是证据主体；判不准报备压在证据之后、追溯之前
（先看数、再看数有多不准、最后看数从哪来）；追溯锚收尾（出处独立成节，
Jupyter Book/Quarto/TIER 三家独立走到同一结论）。

### 2.2 每节必填/选填

| 节 | 必填性 | 必填槽（空槽即校验红，弃权须走 §7 合法形） |
|---|---|---|
| 报告头 | **必填** | 实验名／报告 id（`[A-Za-z0-9._-]`）／status（`final`/`partial`/`superseded`，词表共用 report@1）／纳入轮次清单（一轮一行：轮次 id＋起止或信息量口径）／generator（复算入口：脚本或命令＋版本；形照 report@1 `kind/name/version/argv/script_sha256`）／AI 使用声明区块（§6）／签收块（§6.2） |
| §1 结论先行 | **必填** | 主读数（引读数号）＋区间＋判定（过线/不过线/弃权）＋**所引判据声明版本**＋边界句「绿＝有账、账有据、据未被改，不是内容为真」 |
| §2 预注册对照 | **必填** | 判据声明引用（路径＋版本/commit＋sha256 前 12＋冻结时间，§4）／事前预设读数清单 vs 事后追加读数清单的分界行／偏离记录（有偏离必写「偏离了什么＋原因」；无偏离写「无」） |
| §3 读数表 | **必填** | 四列表头＋至少一行读数（零读数报告＝整表弃权，仍须写明） |
| §4 判不准报备 | **必填** | 每条中心读数的区间/不确定带或弃权标记（§5、§7）／样本量口径（n 多大、有没有排除，排除子句不得省略——paper/facts A4 先例「引用时不得省略排除子句」）／偏倚方向与幅度（STROBE 条目 19 口径：写「往哪偏、偏多少」，不许只写「存在局限」） |
| §5 追溯锚 | **必填** | 原始件清单（工作区相对路径＋sha256 前 12＋定位节）／事实账条目清单（facts id）／复算入口（逐读数或整批）／副本纪律声明（原始件不搬动不改写；如做只读副本，副本 sha256 现算入表——STYLE-EVIDENCE 既有纪律升为模板槽） |
| §A 方法与环境 | 选填 | 跑法、协议面（如 mode=series/bigcard）、环境版本 |
| §B 轮次谱系与多轮对照 | 选填 | parent/derived_from（修订派生不覆盖）；多轮差分视图（本轮 vs 基线） |
| §C 计算资源 | 选填 | NeurIPS 条目 8 三要素：worker 类型/内存/执行时间 |
| §D 失败与 null 结果 | 选填 | 失败分类留档（自主实验室「失败模式分类表」口径）；null/负结果在册（A/B 平台「33.4% ship 率的分母」口径） |
| §E 偏离与变更 | 选填 | 方法/结局变更＋原因（CONSORT 3b/6b/10 口径）；判读词跑后是否动过（动过即红，MANUAL 冻结纪律） |
| §F 引文与出处 | 选填（**引用了外部文献/标准即必填**） | 逐条：引文＋钉版出处 URL＋参考日＋哈希（「钉版官方出处＋参考日」口径） |

### 2.3 四列读数表

§3 读数表固定四列，列名列序不得改：

```
| 读数号 | 读数原文（逐字） | 事实账/原始件锚 | 报告位置回填 |
```

| 列 | 规则 |
|---|---|
| **读数号** | 报告内唯一，形 `[A-Za-z0-9._-]`；约定 `<节字母><序号>`（E1、E2-1，STYLE-EVIDENCE 先例）。与 facts id 同名即视作锚到该 facts 条目 |
| **读数原文（逐字）** | **只逐字摘录、不改写原始读数**（STYLE-EVIDENCE 纪律升为硬规则）。允许紧跟方括号注记，注记属报告层、与原文物理隔开：`[区间 …]`（§5）、`[探索性]`（§4）、`[弃权:不适用|不可得＋一句原因]`（§7）。规范形照 report@1：ratio 写 `n/d`、percent 写 0–100、禁裸浮点精度承诺（precision 单独标） |
| **事实账/原始件锚** | 二选一必填、两条都给更佳。形一：`facts:<id>`（须真实存在于 `facts/*.toml`）；形二：`<工作区相对路径>#<定位节> sha256:<前12>`（路径禁绝对路径禁 `..`，TIER 可搬迁口径；sha256 现算比对）。锚到机读产物（JSONL/CSV/JSON）的读数可升级挂 report@1 探针（§3.2） |
| **报告位置回填** | 本报告内位置（§节/表/行号）。**这一列就是我们的「Reported on page No」**——校验器回查所填位置必须真实存在（EQUATOR 四列表的机械校验落点） |

### 2.4 报告头：AI 使用声明区块与签收块

- **AI 使用声明区块**（§6 分档表填这里）：逐档声明「本报告 AI 参与到哪档、
  哪些段落、哪个工具哪个版本、谁复核的」。五要素（工具名｜版本/模型标识｜
  用途｜是否人工复核｜复核人）缺一即声明不完整。
- **签收块**：签收人／签署时间／核查项清单（逐项勾）／AI 参与段落清单，
  四样缺一＝无效签署（§6.2）。v0 签收落在报告头内的 Markdown 块；
  已有机读伴生件的报告，签收以 `report sign` 六行审阅卡为准（词表共用，
  不另造一套签署词汇）。

### 2.5 词表共用与状态机

- **status**：`final` / `partial` / `superseded`——照抄 report@1 闭集，
  不另造第四态。`superseded` 必须写明取代者报告 id（PROV-O
  `wasRevisionOf`/`wasInvalidatedBy` 语义的文档面）。
- **修订不覆盖**：报告定稿后内容不可变；要改只能新开一份标 `superseded`
  （eLabFTW locking 口径）。链上哈希（追溯锚节）不变是判「改没改过」的锚。
- **value_type / role / probe**：凡机读伴生件出现这些字段，一律用 report@1
  闭集；本规范不发明同义词。

## 3. 数字锚硬规则（TIER 照抄＋本地化）

### 3.1 三条硬规则

1. **每个数字必须脚本产出并可复算**（TIER soup-to-nuts 原文口径：
   "Every computation that modifies the data or produces a result must be
   executed by a command written in one of the scripts"）。报告里每个中心
   读数必须在报告头 generator 或 §5 复算入口给出**复算入口**（脚本路径或
   命令）；给不出的读数不得以「已核」面目出现，只能标 `[探索性]` 或弃权。
2. **每个数字必须带锚**：四列读数表第三列非空（§2.3）。AI 写入的数值同样
   必须携带来源指针，无指针视为未生成、不得进报告（AI 侦察借鉴 7）。
3. **禁手工计算**：人工目视/手抄/口算出来的数字一律不得进报告正文与判定句
   ；手工核对只允许出现在 `cross_check` 位（对应 report@1 `kind=human_text`
   只能作 cross_check 的既有语义）。判读侧「逐数亲算」是**人**的纪律
   （MANUAL §五），不豁免报告侧「数须脚本产出」——亲算的对象是探针产物，
   不是绕开脚本造数。

### 3.2 接 report@1 check 的映射草案（只列不改，实现候批）

| 本规范校验项 | report@1 对应 | 现状可接性 |
|---|---|---|
| 必填槽检查（模板空槽/非法弃权形） | R1（必填字段、枚举、schema） | **需扩**：R1 管的是 report.toml；Markdown 面走 grep lint（§8-2）。升级为机读伴生件后直通 |
| 读数号唯一＋白名单 | R2（metric id 唯一＋`[A-Za-z0-9._-]`） | 同上：MD 面 grep；TOML 面直通 |
| 值规范形（ratio `n/d`、percent 0–100） | R3（值规范与 value_type 一致） | 直通 |
| 锚路径安全（工作区相对、拒 `..`、拒绝对路径） | R4（PATH_ESCAPE 族） | 直通 |
| 机读锚探针复算 | R5（探针重算 == value，±1 末位；探针 `jsonl.count`/`jsonl.count_where`/`csv.cell`/`json.pointer`） | 直通（锚到机读产物时） |
| 每读数必有锚 | R6（必需 source 集合；`kind=human_text` 只能 cross_check） | 直通：叙事类锚＝human_text cross_check 位；主值位必须机读锚 |
| 追溯锚 sha256 现算比对 | R7（锁与磁盘一致；`evidence_digest` 现读现算） | 直通 |
| 定稿摘要完备 | R8（三摘要重算一致） | 直通 |
| 未注册读数标 `[探索性]` | R16（advisory：partial 被引、人工溯源→黄） | **需扩**：新增 advisory 码（照 SPEC-CHECKS §4.4 minor 增码程序，码带域前缀） |
| 判据声明引用完备 | R10（status：partial→黄、superseded→红）部分同构 | **需扩**（同上） |
| 签收四样证据 | `report sign` 六行审阅卡＋signoff 流水 | 直通（机读伴生件）；MD 面走 §8-11 |
| 弃权合法态 | R16 advisory 类 | **需扩**（同上） |

草案纪律：映射只描述「将来能接」；v0 一律先走 §8 grep 级校验，不改
`report.py` 一行。凡将来真增码，照核验槽纪律走：码带域前缀、码表冻结、
只增不改名、双向测试各一例。

## 4. 预注册对照

1. **判据声明必须是可版本化的独立件**（轮次侦察跨领域综合第 14 条：DoE
   设计矩阵、临床 SAP、MLOps YAML、A/B 判据清单、自主实验室候选与阈值——
   五领域共同收敛为「跑前钉判据＝一份可版本化的判据声明」）。判据声明件
   含：主判据（metric＋goal 成对声明，方向＋阈值，不接受「越高越好」空话）、
   护栏指标、预算三类（总轮数上限/超时/轮内早停，MLOps 口径）、判读词。
2. **报告必须引用判据声明的版本号＋位置**：§2 预注册对照节写
   `路径＋版本（commit 或文件 sha256 前 12）＋冻结时间戳`；sha256 现算比对
   （冻结锚同构：跑前冻结、跑后不改，MANUAL 预注册纪律的文档面）。
   只写「我们预注册了」而无版本引用＝未注册（COS 硬条件口径：机制在
   「结果产生前固化」，不在报告里声称）。
3. **事前预设 vs 事后追加强制分账**：§2 里两份清单分列（CONSORT 2025 条目
   10/21d/28 的既有口径）；§3 读数表里凡不在事前清单的读数行必须带
   `[探索性]` 标记并降级展示（不进判定句、只进附录性陈述）。
4. **偏离只须披露、不须免责**（Registered Reports「原则上录用不因结果撤销」
   口径）：偏离记录写「偏离了什么＋原因」即可，判据声明不因结果不利而翻改
   ；跑后改判据＝判读词冻结红线（MANUAL），报告里发现即红。

## 5. 区间与不确定带

1. **中心读数必带区间**（MANUAL 判读纪律「报区间＋不确定带」的文档面；
   TRIPOD 条目 16「performance measures (with CIs)」、NeurIPS 条目 7
   「误差棒须恰当报告并正确定义」同口径）。区间写在读数原文列的
   `[区间 …]` 注记里；原始件只给中心值时，区间须由脚本产出并给出复算入口
   （不许手拍 ±5%）。
2. **样本量与排除子句不得省略**：n 多小、排除了谁、为什么排（paper/facts
   A4 先例：「排除 2 单基线红；引用时不得省略排除子句」）。n 极小的档位
   （如 n<5）直接降级为「描述性观察」，不许出比例判 sentence。
3. **判据阈值引用版本**：§1 判定句与 §4 报备里引用阈值时必须带判据声明
   版本引用（§4-2 形），不许裸引数字阈值。
4. **跨批可比的口径注记**：跨版本/跨盘面读数禁止直比（MANUAL「同盘重算」
   口径）；报告里凡引跨批对照，须注明各侧版本界线（如 cases@commit＋fold
   状态版本）。

## 6. AI 参与披露分档

### 6.1 分档表（ACL 六级 a–f＋ACM 用途二分，裁成我们版四档）

| 档 | AI 干了什么 | 是否披露 | 披露写法 | 依据 |
|---|---|---|---|---|
| **L0 语言级** | 措辞润色、错别字、纯排版 | 免逐段标注；报告头声明区块记一行即可 | 「L0：全文语言润色（工具/版本）」 | ACL a/b；ACM「仅辅助写作」 |
| **L1 检索级** | 找文献、找材料、整理线索 | 免披露；但引用准确性照常规要求（§F 引文与出处照走） | —— | ACL c |
| **L2 结构级** | 提纲、归一化整理、低创文本段落 | **段落级标注＋报告头区块登记** | 段后 `[AI-drafted: <工具>/<版本>]`；区块行「L2：§x §y（工具/版本，复核人）」 | ACL d「标注位置＋已核查＋挂引用」 |
| **L3 判断级** | 新思路、新结论、生成或改写读数 | **必须披露＋逐段人工复核标记**；介入研究链路（出数、出判据、出结论）必须详述方法 | 区块行「L3：§x（工具/版本，逐段复核人，方法描述见 §A）」 | ACL e/f；ACM「介入研究链路必须详述」 |

**红线四条**（Springer 红档＋四家一致，写死）：

1. AI 生成的数值必须带锚，无锚视为未生成（§3-2）；AI **不得**充当
   数值的产生者——数值只能由脚本从原始件/事实账产出。
2. AI 不得署名、不得列为签收人（ACM "under any conditions"）。
3. AI 不得替代判定：过线/不过线的判定句必须出自冻结判据＋机械判卷，
   不出自模型（Springer「AI may support, but must not replace, scholarly
   judgement」）。
4. 把 AI 产出标记为人工产出＝红（Springer 红档"presenting them as
   human-derived"）；敏感数据不得进公共 AI（Nature 红档同源条款）。

### 6.2 人签条款

签收四样证据，缺一＝**无效签署**（视为未签）：

1. 签收人（真人姓名/席位名）；
2. 签署时间（ISO8601）；
3. 核查项清单（逐项勾：读数锚抽验了哪几条／sha256 现算过哪几个／
   探索性标记核过没有）；
4. AI 参与段落清单（与 L2/L3 段落级标记逐一对得上）。

身份边界照 SPEC-REPORT-SYNC §5 如实写明：有 shell 的 agent 技术上可代签，
v0 只提高伪造成本＋全程留痕，不作密码学保证。

### 6.3 责任归属（四家一致口径）

- **AI 永不可署名**（ACM：cannot be listed as authors **under any
  conditions**；Science/ACL 同判）。
- **人类责任不可转移**（Nature："Human accountability is non-transferable"
  ；ACM：署名作者对任何问题内容负全责 regardless of source）：报告准确性、
  引用完整性、偏见审查三项由签收人对**全部内容**负责，包括 AI 产出部分。
- 编辑/判读侧可因 AI 不当使用退回报告（Science"Editors may decline"口径
  的本地面：判读场见到无效签署或红线违例，报告整体退回，不局部打补丁）。

## 7. 弃权合法化

1. **弃权是合法终态**：证据不足时报告对该项**显式弃权**，写法
   `[弃权:不适用｜不可得＋一句原因]`（不适用＝NA 的 Not Applicable，
   不可得＝Not Available——NeurIPS NA 双语义照抄，**两种必须写明是哪种**，
   因为两者可机械判别）。弃权不算失败、算诚实（NeurIPS 官方口径：
   "no 可接受但必须给理由"；诚实写局限不会因此被拒——"a worse outcome
   might be if reviewers discover limitations that aren't acknowledged"）。
2. **弃权 ≠ 静默缺槽**：必填槽既不填、又不写合法弃权形＝校验红；
   写了合法弃权形＝过校验（NeurIPS 条目 2 的判别式：「NA＝无局限；
   No＝有局限但没写」的槽位版）。判分/判读侧把「硬答」与「弃权」分开记账
   ，防「激励灌水」——格局评测的既有教训：判分只奖答对不奖弃权时，
   被评方会硬答。素材佐证：PaperQA2 官方评测保留 "Insufficient
   Information" 合法选项（AI 侦察 §2.2）。
3. **弃权的连带面**：主读数弃权＝判定句只能是「本项弃权」，不得给出
   过线/不过线；§4 判不准报备里弃权项须列「缺什么证据、补上需要什么」
   （给下一轮的判据声明供料）。
4. **豁免同理**：变异对照「豁免」态（等价变异体不可判定——记档别硬掰）
   在报告里按弃权形落账，不硬凑读数（MANUAL §七既有口径的文档面）。

## 8. 机械校验清单（每条：校验什么＋怎么机械判）

v0 全部 grep/现算级，零 LLM、零新依赖；编号 C1–C14，与 §3.2 映射草案对照。

| # | 校验什么 | 怎么机械判 |
|---|---|---|
| C1 | 章节固定序与标题名 | 五个固定标题（`## §1 结论先行` 等）按序各出现一次；选填节标题在固定节之后 |
| C2 | 必填槽非空、弃权形合法 | 扫模板标记 `【必填：…】` 无残留；出现 `[弃权:` 必须匹配 `不适用|不可得` 且带原因句，否则红 |

| C13 | 弃权连带 | 判定句为过线/不过线者，其主读数行不得带弃权标记；带弃权标记的主读数，判定句必须是「本项弃权」 |
