# 方法论 → 命令：四道工序的接法

这是一份**约定**，不是新功能。它说明一种写作方法论可以怎样落到本仓已有的命令上，不新增判据、不改退出码、不进 `factscribe/` 包。

## 四道工序

| 阶段 | 谁做 | 调什么 | 过线标准 |
|---|---|---|---|
| 1 计划 | 机器 | `factscribe brief <项目>` | 节清单、可用主张与数字、术语表、篇幅预算齐全 |
| 2 生成 | 人或模型 | 无（按简报写正文） | —— |
| 3 校验 | 机器 | `factscribe audit <项目> --build` | 0 红；黄逐条有人看 |
| 4 润色 | 人或模型改，机器验收 | `factscribe polish --plan <项目>` → 改 → `factscribe review --before 旧 --after 新` | `review` 判「通过」 |

## 用 `gate.sh` 跑这四步

```bash
./gate.sh brief  <项目>          # 阶段 1：出写作简报
./gate.sh check  <项目>          # 阶段 3：审账 + PDF 回检
./gate.sh plan   <项目>          # 阶段 4 前半：出改写工作单
./gate.sh accept <旧目录> <新目录>  # 阶段 4 后半：验收改写
```

阶段 2 没有命令——那是写作本身，工具不参与。

## 三条边界

1. **阶段由命令选，判据不感知阶段**。同一段文字在 `brief`（起草参考）和 `review`（改写验收）里看到的结果必须一致，否则读数不能当证据。
2. **不改退出码语义**。`gate.sh` 原样透传底层命令的退出码：0 绿、1 红、2 配置错、3 黄。
3. **不新增依赖**。脚本是纯 POSIX shell，只调用 `python3 -m factscribe`。

## 换一种方法论怎么接

把上表的「阶段」换成别的方法论，把「调什么」换成已有命令即可。例如：

| 方法论 | 阶段 | 对应命令 |
|---|---|---|
| 七步章节闭环 | 起草后 / 定稿前 | 两处都跑 `check` |
| BOPPPS 教案 | 参与式学习后 | `check`（数字与引用） |
| 费曼学习法 | 解释后 | 无对应（那是理解，不是事实核对） |

**凡是「核对事实与引用」的环节，都能接；凡是「判断讲得好不好」的环节，工具不接。**
