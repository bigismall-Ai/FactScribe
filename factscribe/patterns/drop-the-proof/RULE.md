# drop-the-proof｜删掉反射式解释，让断言自己站住

## 治的判据

- 错误码：EXPLAINER_DENSITY、JUSTIFY_CHAIN
- 现象：断言之后立刻补一句解释，段落结尾总要收个尾，读起来像答辩。
  `EXPLAINER_DENSITY` 数句首解释性套语的密度；`JUSTIFY_CHAIN` 抓同段
  连续两句、或连续两段都用解释句收尾的反射式解释。

## 必做

1. 让一半断言独立成立：删掉紧跟其后的解释句，读一遍——事实、数字、
   条件都还在，就算站住了。
2. 把证据挪到真正需要它的地方：读者会追问「凭什么」的那一处留一次，
   其余位置不再重复举证。
3. 一段最多解释一次：同一段里出现第二句「这说明／也就是说」就删掉，
   或者把它并回被解释的那一句。
4. 解释句若承载新信息（新的数字、条件、反例），先把它降级成普通陈述句，
   再判断是否还需要保留。
5. 改写只动措辞与句序，事实、数字、引用保持原样。

## 禁做（含反例）

- 禁把解释句改成同义的另一句解释。反例：
  `数字全对，结论照样可能是错的。这是最常见的一种误会。` →
  `数字全对，结论照样可能是错的。人们常在这里看走眼。`
  （第二句还是替第一句补解释，只是换了说法。）
- 禁用另一个套语替换原套语。反例：`也就是说` → `换句话说`。
- 禁为了凑「一段只解释一次」把解释句搬进相邻段——链还在，只是挪了位置。
- 禁顺手删掉解释句里的事实、数字、条件或引用。反例：
  `区间很宽，这说明样本只有十六单。` → `区间很宽。`（丢掉十六单。）
- 禁改成自问自答（「为什么？因为……」），那是同一种答辩腔的另一种写法。

## 改写示例（旧 → 新）

| 旧 | 新 | 说明 |
|---|---|---|
| `数字全对，结论照样可能是错的。这是最常见的一种误会。` | `数字全对，结论照样可能是错的。` | 断言已经站住，后半句只是补解释 |
| `它证明的是「账、据、文三者自洽」。它不证明「论文为真」。` | `它保证账、材料、正文三者对得上，材料没被换过。论文结论对不对，它不知道。` | 把举证式自述改成可核验的陈述 |
| `主对照只有十六单。这意味着区间宽到十三到十九单。` | `主对照只有十六单，区间宽到十三到十九单。` | 两句并一句，解释变事实 |

旧 → 新不删数字（十六、十三、十九），不删限定，不删引用。

## 验收命令

```bash
env PYTHONPATH=src python3 -m factscribe prescribe drop-the-proof --json
```

改完把正文换进项目后再复核（文档模式）：

```bash
env PYTHONPATH=src python3 -m factscribe style --doc <文件> --json
```

两条判据不再出现即闭合；只降密度但链还在，不算改完。
