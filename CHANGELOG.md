# Changelog

All notable changes to factscribe. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
versions follow [SemVer](https://semver.org/).

factscribe is a pre-1.0-grade tool in behaviour but its gate contract is already
frozen (see `SPEC-V1.md` §5): exit codes and violation codes are the public API
and will not change without a major version bump.

## [Unreleased]

### Changed
- **The audit closure now fails closed on out-of-project `\input` targets, the write API closes its cross-origin hole, and the fullwidth decimal point stops splitting one number into two (five-defect sweep batch, stacked on the strict Python-3.10 TOML parser)** — five defects found by a full-repo sweep against `origin/main` are fixed together, each with a negative regression test (source reverted, the new cases go red). (1) **`INPUT_OUTSIDE_PROJECT` (red, exit 5) is now implemented** — the spec has listed this code since `SPEC-V3.0.md` §8.1, but the tree never implemented it: `config.py::add_ref` dropped a `\input` target whose resolved path left the project root without recording it anywhere, so the closure silently skipped it and `audit` still reported green ("0 red / 0 yellow — every number and citation is accounted for") while that file's numbers were never scanned. Such a target is now recorded in `cfg.outside_inputs` (same shape as `missing_inputs`) and judged red `INPUT_OUTSIDE_PROJECT` (exit 5); a dangling target keeps `INPUT_TARGET_MISSING`, so "exists but outside the project" and "does not exist" no longer collapse into one verdict. The `bundle` closure gate fails closed on the same list. (2) **`serve`'s `do_PUT` now checks the request origin** — it was the only one of the four HTTP methods without the `_origin_ok` gate (GET/POST/DELETE all had it), and `PUT /api/sections` is the only endpoint that overwrites paper-body `.tex` files, so any page open in the browser could rewrite a section cross-origin (in `--no-token` mode even without a token). The gate matches the other three: no `Origin` header is allowed through, an `Origin` that is not this listener's own address is refused with 403 `CROSS_ORIGIN` — which also makes the `--no-token` help text ("only same-origin requests to this listener's address") true rather than aspirational. The Node proxy sends no `Origin` header, so the Miniapp write path is unaffected. (3) **The fullwidth full stop `．` (U+FF0E) is now a decimal point** — fullwidth digits were already digits (the `\d` in `_NUM_RE` matches them in Unicode mode and `Decimal` parses them) but the decimal point was ASCII-only, so `５６．２５` was cut into `５６` and `２５`, producing a spurious `BOUND_MISMATCH` red whose message pointed at the wrong number (and, if the ledger happened to hold 56 or 25, a mis-binding onto an unrelated fact). Fullwidth is now equivalent to halfwidth (`50．5` = `50.5`, and still not `505`); the substitution is length-preserving, so columns and offsets do not move. (4) **Exit codes 5/6/7/8/9 no longer render as `?`** in the human conclusion line (`report.py::_status_word` mapped only 0–4, so a red gate could print "1 red / 0 yellow → ? (exit 5)"), and both READMEs' exit-code tables now list 5 — the code `audit` really exits with. (5) **`BAD_SOURCE_PATH`'s message says "absolute path" once** (the template already listed it and the ternary appended it a second time). Measured impact: across all 26 fixture/example projects, no verdict changed — 0 green projects turned red — and the golden baseline (`tests/golden/audit_findings_baseline.json`) is untouched.
- **`textreuse`: multi-scale word windows plus a sentence-containment layer — the PAN improvement batch (P-165)** — the literal layer used to run a single fixed 8-word window, and one word-level perturbation was enough to cut the match in half: on the PAN-PC-11 exam paper the `none` tier (which the corpus labels as verbatim) scored **1/20** cases at ≥0.8 character coverage against a required **≥18/20** (FAIL), while the clean pair scored a clean PASS — the literal-layer claim failed on verbatim-ish text and passed on clean text, the worst combination. Two changes, both still literal-layer, both still zero LLM / zero network / stdlib-only. (1) **Multi-scale windows**: the tool now runs `n∈{8,5}` by default and merges the same-source segments across scales by **union interval** (a passage broken by word-level noise gets re-joined); `--n N` keeps the old single-window mode and `--scales 30,15,8,5` allows a custom scale set. (2) **Sentence-containment layer** (on by default, `--no-sentences` turns it off): both sides are split into sentences and each candidate sentence pair is scored by word-set overlap `|∩| ÷ |shorter side's word set|`, default threshold **0.7** (`--sentence-threshold`), and a pair at or above threshold is reported as an overlap segment located on both sides' sentences. The performance guardrail is kept: candidate sentence pairs are first coarse-filtered by the smallest scale's word windows, so no O(n²) all-pairs comparison happens, and the candidate set is capped. Sentence splitting follows the prose rules: terminal punctuation splits, hard line wraps do **not**, blank lines do, and abbreviations (`Mr.`, `e.g.`), decimals (`3.5`) and initials (`J.`, `U.S.`) do not split. Every reported segment now carries a **match source** (`match_source`: `word-window` / `sentence-containment`, plus the scale and the containment ratio) in both the human report and the JSON, so a hit can be attributed to the window layer or the sentence layer. Exit codes are unchanged (**0** / **1** / **2**) and the JSON keeps every previous key (new keys are additive). **Capability boundary restated truthfully** — the card still covers the *literal* layer only, now meaning both verbatim copying **and near-literal mechanical overlap** (word windows plus sentence containment); semantic rewrites are still out of scope and **漏检属语义层，本卡不覆盖**. The boundary string in the human report and in the JSON `boundary` field, plus both READMEs, were updated to say exactly that. Module `factscribe/textreuse.py`; new opaque codes `TR_SENTENCE_THRESHOLD_RANGE` / `TR_SENTENCE_MIN_WORDS_RANGE` (stay out of the code vocabulary); no other module's behaviour changes; the version number does not move. The PAN re-run (P-157 criteria, same seed 20261118, same sampling, same distractors — `experiments/fs-textreuse-pan/`) is in `REPORT-PAN-V2.md`; the evaluation set (the `none` and `clean` tiers) was run **once**, with the dev/eval separation mechanically enforced by the runner.
- **`style`: three criteria re-cut to the P-152 final ruling (user sign-off on the calibration batch + three-axis blind review)** — the prose gate kept its mechanics but three criteria changed what they call a defect, and the evidence for each is recorded in the config comments. (1) **`HEADING_MALFORMED` withdrawn as a family**: the blind R3 axis (“does this heading's formatting follow publication convention?”, n=20) found **0/20** dual-seat upheld, 14/20 dual-seat clean, 6 split — every hit was an ordinary field convention (colon subtitle, parenthesised acronym, hyphenated compound, heading question). The family is removed from `factscribe/style.py` (pattern, `heading_period_exempt` lookup, metric and read-out) and from `style-rules.toml`; the `heading-malformed` prescription stays, because `HEADING_RELATION_CHANGED` still uses it. (2) **`HEADING_ECHO` narrowed to literal high repetition**: it now reports a section-opening sentence only when the heading's content words recur *contiguously* in that sentence (≥ 2 content words, `heading_echo.literal_min_terms`) **and** the sentence adds at most `thresholds.heading_echo_max_new_terms` (3) new content words — i.e. the opening is a literal echo of the heading, not a synonym paraphrase and not merely a transition opener. The old “no new content at all” and “opens with `In this section, we …`” branches are gone: in the 28-paper corpus that opener is normal prose in every hit. The repeat count of the same opener stays a detail field, never a trigger. (3) **`LIGHT_VERB_NOMINALIZATION` narrowed to heavy use**: the blind R1 axis (n=20) upheld only 2/20 — and the same phrase (“perform experiments”) is judged clean in a paper that uses it once and defective in a paper that uses it 15 times, so heaviness has to be counted per document, not per phrase. The rule therefore reports only when one project reaches `thresholds.light_verb_doc_min` (5) hits, and the low-precision group (`article_verbs`: make/give/take/have/do/reach/achieve/establish) is retired outright — all 7 of its sampled hits were judged “no defect” by both seats. Config: `light_verbs.article_verbs = []`, `thresholds.light_verb_doc_min = 5`, `thresholds.heading_echo_max_new_terms = 3` (replaces `heading_echo_min_new_terms`), `heading_echo.literal_min_terms = 2`. Re-gates on the 28-paper corpus: `HEADING_MALFORMED` 48 → 0 findings, `HEADING_ECHO` 39 → 6, `LIGHT_VERB_NOMINALIZATION` 108 → 34, median triggered 3.5 → 1, median findings per 1k words 1.255 → 0.381, and the `paper-b` / `paper-b-zh` anchors stay at 0 findings.
- **`_mini_toml` (the bundled TOML fallback used on Python 3.10) learns inline tables; audit output is now byte-identical across Python 3.10–3.14; golden baseline re-frozen**: the fallback parser's array splitting tracked quotes but not braces, so an array-of-inline-tables value such as `display = [{ text = "0.9", round_to = 1 }]` came back on 3.10 as a list of two raw strings (`'{ text = "0.9"'` / `'round_to = 1 }'`) — the audit then emitted two garbled `DISPLAY_INCONSISTENT` findings, while stdlib `tomllib` on 3.11+ correctly yields one finding (`display '0.9'`). `_mini_toml` now splits arrays and inline tables with brace/bracket depth awareness and parses inline tables `{ key = value, … }` (nested values recurse through the same value parser), so 3.10 output matches 3.11+. The 26-project golden baseline (`tests/golden/audit_findings_baseline.json`) was re-frozen on the fixed parser with the reason recorded in its `note` field: for the one affected locked project (`fixtures/hostile/R2-ROUNDTO`) the two mis-parsed findings collapse into one correct `DISPLAY_INCONSISTENT` finding and the exit code (1) is unchanged; every other project stays byte-identical. Also fixes the legal-slot test fixture, which appended a second `[checks.legal]` table header — tolerated by the lenient fallback but invalid TOML (tomllib: `Cannot declare ('checks', 'legal') twice`); appended keys now land inside the template's existing `[checks.legal]` table.
- **`_mini_toml` (the bundled TOML fallback used on Python 3.10) is now strict: broken TOML is refused instead of silently accepted, so Python 3.10 reaches the same verdict as 3.11+** — the fallback parser was lenient: a malformed table header such as `[[ref]` was taken as a table literally named `[ref`, and an unterminated string such as `id = "X1` was swallowed as a bare word. Both are invalid TOML, and stdlib `tomllib` rejects them on 3.11+ — so on 3.10 the `refs` and `figures` gates answered "let it through" for a broken ledger while 3.11+ answered "refuse" (exit 2). That is a fail-open gate on one leg of the CI matrix, and the same broken file also yielded a different verdict per interpreter. The fallback is rewritten as a strict subset parser whose accept/reject decisions **and** parsed values match stdlib `tomllib` exactly: tables, arrays of tables, dotted table names, dotted keys, basic/literal/multi-line strings, arrays, inline tables, integers, floats, booleans and date-times are read; everything outside that subset (broken headers, unterminated strings or brackets, bare-word values, duplicate tables or keys, trailing junk on a line) now raises. Broken input travels the existing `ConfigError` channel, so the exit code stays **2** (config error) and no violation code changes. Measured by diffing the fallback against stdlib `tomllib` on the same text: all 107 TOML files in the repository parse to byte-identical dictionaries (no false positives on legal files); a 107-case hand-built accept/reject battery, a second 54-case battery, 40,000 mutation-fuzzed documents and 20,000 randomly generated valid documents agree with `tomllib` on every verdict and every value. That diffing also found two gaps in the first cut of the strict parser, both now fixed: **CRLF line endings** (the strict rewrite rejected Windows-written files that the old line-based parser read fine — `tomllib.loads()` normalizes CRLF to LF at the entry point and so does the fallback now) and **control characters** (the fallback accepted `\x01` and a bare `\r` inside strings and comments where `tomllib` rejects them). New negative locks live in `tests/test_toml_compat.py` and `integrations/factscribe-legal/tests/test_toml_compat.py`; the golden baseline (`tests/golden/`) is untouched.
- **The other two Python-3.10 TOML parsers in the tree are closed too (`factscribe/report.py`, `integrations/factscribe-legal/factscribe_legal/_toml.py`)** — the strict-fallback fix above only covered `factscribe/config.py::_mini_toml`, but the tree held two more 3.10-only parsers and both were lenient in the same way (bad input silently accepted ⇒ a gate answered "let it through" on 3.10 while 3.11+ answered "refuse"). (1) `factscribe/report.py` carried its own 3.10-only report parser (210 lines), there only because the old fallback did not understand inline tables: it accepted bare-word values, silently overwrote duplicate keys, reused duplicate table headers and returned date-times as plain strings, so a broken report could be "read" on 3.10 and rejected on 3.11+. Report TOML now goes through `factscribe.config.load_toml` on every interpreter (one path, one verdict) and the duplicate parser is deleted (-209 lines); the error code for an unreadable report is unchanged (`BAD_TOML`). (2) The legal package's own `mini_loads` silently overwrote duplicate keys, reused duplicate table headers, accepted leading-zero integers (`01`), mis-parsed multi-line strings (`"""x"""` came back as `""x""`) and accepted trailing junk after a closing quote — all now rejected (fail closed, same as `tomllib`). Its documented subset contract is unchanged (inline tables / multi-line strings / date-times are still refused rather than guessed) and its own sample ledger still reads identically. The module docstring and `integrations/factscribe-legal/README.md` carried a now-stale reason for not reusing the upstream parser (upstream's fallback has since been rewritten strictly); both are rewritten to state the current reasons (standalone installability plus a deliberately narrower fail-closed subset).
- **Breaking**: protocol literals hard-cut to the `factscribe` namespace — project schema `factscribe-project/3.x` (the older `factscribe/3.x` alias still reads), fact schema `factscribe-fact/3.x`, stamp `factscribe-stamp/3.0`, report `factscribe-report/3.0`, magic comments `% factscribe:generated` / `% factscribe:table-map`; the deprecated old-name config fallback is removed — only `factscribe.toml` is read, so data written under the previous old-name config file or schema strings is no longer read. The on-disk working directory was renamed to `factscribe-dev`.
- **Bare `[checks]` now walks the check slot (behavior notice)**: a `[checks]` section present but without `packages` used to behave exactly like no section (the M1 default); per ruling 3 of the approved SPEC-CHECKS (2026-11-16) it now runs the slot with the default `packages = ["paper"]`. For such projects the audit output gains a `domain` key on every finding and a `summary.by_domain` count — additive keys only; the findings themselves, the exit code and the human report are otherwise identical to a direct run. Projects without any `[checks]` section are unaffected byte-for-byte. The 26-project golden baseline (`tests/golden/audit_findings_baseline.json`) was re-frozen with the reason recorded in its `note` field: every locked project has no `[checks]` section, and the per-project findings and exit codes are byte-identical across the re-freeze.
- **`factscribe_legal` CLI enters a deprecation window (ruling 6)**: each of the five subcommands (`fetch`, `verify`, `verify-cn`, `verify-case`, `verify-it`) now prints one notice line after argument parsing — 「提示：本命令是单域调试入口（废弃窗口不限期，功能保留）；正式报告走 factscribe audit [checks]（单命令双域）。」 — pointing at the slot path for formal cross-domain reports. Functionality, options and exit codes are unchanged; the window is open-ended and the commands stay supported as the single-domain debugging entry.
- **The local release gate (`scripts/preflight-ci.sh`) is green on Python 3.10 again — the 3.10 leg now carries determinate assertions instead of two skipped cross-checks** — the preflight gate treats *any* skipped test as "the local run lost coverage" (it exists because the PDF layer must really run on a machine that has poppler, while the CI runner usually cannot install it). The strict-Python-3.10 TOML fix added `tests/test_toml_compat.py`, whose two stdlib cross-checks (`test_matches_stdlib_when_available`, `test_stdlib_also_refuses_broken_input`) could only run where stdlib `tomllib` exists — so on 3.10, the one interpreter that actually uses the bundled fallback parser, they skipped, and the gate went red with "poppler is installed but PDF cases were skipped". **The gate itself is unchanged** (still: poppler present ⇒ zero skips; the PDF-layer detection is untouched) and so is every PDF case. What changed is the cause: the standard library's verdict on every sample is now **recorded in the test file itself** (sample table, third column — accepted → the parsed dict, refused → refused), measured from stdlib `tomllib` on 3.11/3.12/3.13/3.14 (identical on all four). Every interpreter now asserts the fallback parser against that record — 3.10 included: 15 exact dictionaries and 20 refusals — and 3.11+ re-checks the record against the live `tomllib` on every run, so a stale record fails loudly instead of drifting silently. Net effect: the 3.10 leg is **stronger** than before (it used to skip the very comparison that matters most there) and the local release gate is green without any gate relaxation; the gate's failure message now names what it really checks (a skipped case, not necessarily a PDF one). The tree also carries a second file of the same name, `integrations/factscribe-legal/tests/test_toml_compat.py` (the legal package's own TOML layer); the two cannot collide — CI and preflight run the two discovery sets in separate processes, and a single repo-wide discovery collects 0 cases — and the file now records that. No behaviour, exit code or violation code changes; the golden baseline (`tests/golden/`) is untouched.

### Added
- **Dual-directory literal-overlap detection (`factscribe textreuse`) — the literal layer of duplicate checking, MVP (CARD-G6)** — two manuscripts that share a paragraph look like two manuscripts until somebody diffs them by hand, and the hand diff only finds what the eye happens to catch. New subcommand `factscribe textreuse <目录A> <目录B>`, zero LLM / zero network / stdlib-only (`bisect` / `re` / `dataclasses` / `pathlib`; zero new dependencies, zero network). It collects `.tex`/`.md`/`.txt` recursively (`--ext` extends the list), normalises the text (whitespace folding, LaTeX comment lines dropped by default — `--no-strip-comments` keeps them — LaTeX commands and their braced arguments dropped as layout skeleton, case folding), tiles word-level n-grams (default `n=8`, `--n` accepts 5–20), and finds literal overlap across the two sides; adjacent hits merge into segments. CJK is tokenised per character (Chinese has no spaces, so per-word tiling would not step), Latin and digits per word. The report gives, per segment, both sides as `文件:行-行` plus the overlapping token count, and a per-file-pair summary: how many tokens of the A-side file are duplicated (`A 侧占比` = overlap ÷ that file's total tokens) and how much of the B-side file is covered. **Zero configuration**: a bare directory of `.txt` files runs as-is — no `factscribe.toml`, no project declaration (the outsider lesson from G2-FIX). Exit codes follow the house rules: **0** = no segment above threshold, **1** = overlap found (every segment listed), **2** = usage error (directory missing, `n` out of range, one side has no readable file). Comparing a directory with itself is refused with **2** and the message 「自身对账无查重意义」 — self-comparison would report every file against itself. **Capability boundary, stated verbatim in every human report and in the JSON `boundary` field**: this card covers the literal layer only — rewrites, laundering and AI assembly are semantic-layer, out of scope, and **漏检属语义层，本卡不覆盖** (a miss belongs to the semantic layer, this card does not cover it). The semantic/rewrite layer is identity-adjacent and awaits its own ruling (P-139/P-143). New module `factscribe/textreuse.py`; codes carry the opaque `TR_` prefix and stay out of the code vocabulary; no existing module's behaviour changes; the version number does not move. Python total 1625 (1595 before this change, +30 new tests in `tests/test_textreuse.py`).
- **Submission artifact bundle (`factscribe bundle`) — closure collection, a checklist gate, and a journal-configurable gate surface (CARD-G4)** — every material in a paper has its own gate and its own ledger, but handing the paper to a journal means shipping dozens of files, and today that is done by hand: miss one (typically a per-figure CSV or the evidence freeze file) and the reviewer gets an unreproducible package; ship one too many and nobody notices. New subcommand `factscribe bundle <project>` plus `factscribe bundle --verify <package>`, zero LLM and stdlib-only (`hashlib` / `json` / `re` / `shutil` / `copy` / `dataclasses` / `pathlib`; zero new dependencies, zero network). Three steps: **(1) collection** — the `\input`/`\include` closure from `main.tex` (the existing `config.load_sections` closure algorithm is **called, not copied**: the start point is swapped to `main.tex` for v1 projects, while a v3 project's own `root_tex` / `section_files` declaration is respected), plus `refs.bib`, `figures/` (per-figure CSVs included), `tables/`, `facts/*.toml`, the **signed** copies under `runs/` (a run group counts as signed when it contains a `*.signoff.toml`; unsigned groups enter the inventory only and stay out of the package unless `--runs-mode full`), and the three audit files (`audit/evidence.lock`, `audit/evidence-log.ndjson`, `audit/matrix.md`). **(2) the checklist gate** — each item judged mechanically, every item reported in one of three states (pass / fail / waived), and any failing item exits **1** with the items listed; a dangling `\input` in the closure blocks first (fail-closed, as `KNOWN-GAPS.md` R-05 already is). The built-in items are `BUNDLE_CLOSURE` (closure complete, no dangling or unparsable target), `BUNDLE_FIGURE_CSV` (every figure has its per-figure CSV — the existing `FIGURE_UNVERIFIED` judgement, existence only; generation is CARD-G2's business), `BUNDLE_BIB` (no missing/duplicated bib key and no entry without a stable identifier), `BUNDLE_EVIDENCE_LOCK` (the freeze file is present, not unfrozen and not stale — waived when the project never enabled the evidence stamp), and `BUNDLE_AUDIT` (the audit reports no red). **(3) export** — the package directory plus `MANIFEST.sha256` (one sha256 line per file, in `shasum -a 256` format, so the receiving side can run `shasum -a 256 -c MANIFEST.sha256`) and `BUNDLE-MANIFEST.json` (the inventory: what was collected, what is listed but not shipped, which exclusions applied, the gate item by item). `--verify` re-computes every manifest line and reconciles the file count, naming any mismatch, missing or extra file, and exits **1** on any of them. **Journal differences live in the project, not in the code** (user ruling): the project root may hold `bundle-checklist.toml` declaring **extra checks** (each a name plus one of three mechanical forms — `exists` / `glob_min` / `regex`) and **exclusions** (file-mode = the file stays out of the package; line-mode = matching lines stay out of the package content; no semantic judgement, ever). A broken configuration exits **2** and names the offending entry. The tool names no journal anywhere. Two deliberate readings are recorded here: the audit item blocks on **red**, not on the raw exit code — a strict "exit 0" reading would make the gate unusable for exactly the project shape the work order names (a G2-generated `figures/gen/<名>.tex` is a standalone chart source outside the audit closure and is reported `UNSCANNED_TEX`, yellow), and the iron rule forbids changing existing audit behaviour — so yellow findings are listed in the item's detail instead; and the package directory defaults **outside** the project (`<project>.bundle`, `--out` overrides it), because a package left inside the project would put `.tex` copies where the audit's coverage report sees them as closure-external files and change the source project's audit readings. New module `factscribe/bundle.py`; codes carry the opaque `BUNDLE_` prefix and stay out of the code vocabulary; exit codes follow the house rules (0 green / 1 gate red / 2 usage or configuration). Python total 1595 (1567 before this change, +28 new tests in `tests/test_bundle.py`).
- **Ledger-driven chart pipeline (`factscribe figures`) — generate a figure from the ledger, then re-account it against the ledger on four faces (CARD-G2)** — the ledger hashes every number it holds, but drawing a figure meant copying those numbers into some other plotting tool: the numbers inside the picture then sat outside every gate, and the picture became a free-floating set of numbers. New subcommand family `factscribe figures` with two actions, zero LLM and stdlib-only (`csv` / `io` / `re` / `dataclasses` / `pathlib`; zero new dependencies, zero network): the human writes the chart spec `figures/*.fig.toml` (**chart kind** `bar` / `line` / `table`, axis labels, caption, and the data points **as fact-id references only**), and the machine executes. **`figures gen <project>`** reads the specs plus `facts/*.toml` and mechanically produces, per figure, `figures/gen/<名>.tex` (pgfplots code — a standalone document that compiles to `figures/gen/<名>.pdf`, which the body then `\includegraphics`), `figures/gen/<名>.csv` (the per-figure data — the reconciliation object the existing `FIGURE_UNVERIFIED` judgement already looks for next to an included graphic), and `figures/gen/<名>.bind.toml` (the binding table: every data point ↔ fact id ↔ the value and `source_sha256` at generation time), plus a project-level `figures/bind.toml` holding the same points grouped by figure; the two binding tables are written from the same in-memory data and `figures check` cross-verifies them. The **hard gate** is the spec: a data point must cite a fact id, so a bare number in the spec is a configuration error (**exit 2**, `FIG_BARE_NUMBER`) — one number in a picture that cannot be walked back to the ledger never gets drawn; the same exit-2 treatment covers an unknown chart kind (`FIG_SPEC_BAD_KIND`), missing data points (`FIG_SPEC_NO_POINTS`), an unknown spec key (`FIG_SPEC_UNKNOWN_KEY`), a non-plottable fact value (`FIG_SPEC_UNPLOTTABLE`) and mixed units on one axis (`FIG_SPEC_UNIT_MIXED`); a data point whose fact id is **not in the ledger** is **exit 1** and names the id (`FIG_FACT_NOT_FOUND`). A spec that is broken produces **no artifacts at all** (no half-generation); a figure whose points fail to resolve is skipped while the sound figures are still written. Regenerating over existing artifacts first **prints the diff against the old binding table** (old value → new value, old `source_sha256` → new) before overwriting. **`figures check <project>`** compares the four faces point by point — human spec ↔ binding table ↔ per-figure CSV ↔ current ledger: unequal counts (`FIG_SPEC_DRIFT` / `FIG_CSV_DRIFT`), a value that no longer matches the ledger (`FIG_VALUE_DRIFT`), a `source_sha256` that no longer matches (`FIG_SOURCE_DRIFT`), a fact that has vanished from the ledger (`FIG_FACT_NOT_FOUND`), a hand-edited CSV (`FIG_CSV_ROW_DRIFT`) and missing artifacts (`FIG_ARTIFACT_MISSING`) are all listed **point by point** and turn the command red (exit 1); **the ledger moved but the figure was not regenerated is always red** — the mutation case is registered as an acceptance item. Value comparison follows the FACTS-SCHEMA.md §11.1 equivalence rule (`10/16` ≡ `0.625` ≡ `62.5%`, no rounding tolerance). Identity review: the chart kind and the spec are the human's, the machine only guarantees that every number on the picture can be walked back to the ledger — there is no "smart chart recommendation" here. A project with no specs reports "无图可生成" and exits 0 (skip, never a silent pass). New module `factscribe/figures.py`; all codes are opaque data keys (`FIG_` prefix) and do not enter the code glossary. `audit` is untouched: the generated artifacts satisfy the existing `FIGURE_UNVERIFIED` judgement on their own (the per-figure `.csv` sits next to the included PDF), and the yellow card disappears with zero changes to the judgement path. ### Changed
- The Mini App now lives at `integrations/minifactscribe/` and presents itself as **MiniFactScribe** (plugin id `minifactscribe`, surface path `/minifactscribe`). FactScribe stays the engine; the app name makes the layer explicit instead of pretending the UI is the whole product. The old `factgate` name was an internal port label that had leaked into the UI. Static assets, REST routes, logger event names, the Node test paths and the conformance docs were updated in one sweep; the browser falls back to the old `factgate.tab` localStorage key so an existing tab preference survives. Installed copies under the old plugin id keep their own data directory and must be reinstalled under the new id; nothing in the Python package changed.
- CI: the Python matrix now includes 3.13 and 3.14 (previously 3.10–3.12), because `requires-python = ">=3.10"` has no upper bound and the project is developed on 3.14. A separate `wheel install` job builds a real wheel, installs it into a fresh venv and runs `prescribe --list` plus a Chinese `style --doc`, so the runtime-data packaging gap cannot come back silently.
- `style`: `NUMERAL_DENSITY` is off by default (batch 131). The built-in threshold is `null` (do not judge); the metric and the per-section readout are still computed, but no finding is produced, nothing enters `fired`, and the exit code is unchanged. The implementation and configuration remain: an explicit non-negative number in `[thresholds] numeral_density` restores the old behaviour, and `polish --plan` simply stops emitting those entries while the threshold is null. Reason: the criterion induced evidence deletion — a model lowered the density by replacing core numbers with "nearly every" / "most of them" / "some", leaving the audit green and the section's argument empty.

### Fixed
- **The web workbench no longer flattens a CRLF manuscript to LF when a section is saved** — the editor is a `<textarea>`, and the HTML specification says a textarea's API value normalises line endings to LF (measured on this machine: Chrome 158 headless turns `\r\n` and a lone `\r` into `\n` inside `textarea.value`). The browser therefore hands the server an LF-only body, and the engine wrote that body back verbatim (`workbench.write_section_data` → `textio.write_text_exact`, `newline=""`, no translation) — so **one save turned a CRLF `.tex` into an LF one**: the numbers, the `\fact{}`/`\cite{}` protected surfaces and every token were untouched while the whole file's line endings were replaced, which breaks 「保存必须逐字保留正文内容」. The write side now restores the line endings from the file's own bytes: `textio.restore_newlines(original, new_text)` re-attaches, line by line, the terminator each line already had on disk (CRLF stays CRLF, LF stays LF, a mixed file keeps its per-line mix, lone CR included), gives **newly typed lines** the section's dominant terminator (`dominant_newline`), and leaves a caller's explicit CRLF/CR untouched — the text's content is never rewritten, only the terminator style is. `workbench.write_section_data` calls it with the exact bytes of the file it is about to overwrite, so both write paths (HTTP `PUT /api/sections` and MCP) keep the section's own line endings. ## [1.0.0] — 2026-11-07

### Added
- **Inline binding**: `\fact{A1}` (or `[[fact:A1,A3]]`) binds a line's numbers to
  facts. Every number on a bound line must be a token of that fact's `value`,
  else `BOUND_MISMATCH` (red). Numbers that resolve to a fact but are not bound
  are `UNBOUND_NUMBER` (yellow); numbers that resolve to nothing are
  `UNMATCHED_NUMBER` (red).
- **Provenance chain**: `source_sha256` is recomputed on every run; a missing or
  mismatching hash is red. `results/MANIFEST.toml` is a human-signed list of
  `path -> sha256`; unsigned artifacts are yellow (`UNSIGNED_RESULT`), a missing
  manifest is yellow (`NO_MANIFEST`).
- **Value literal check**: `VALUE_NOT_IN_SOURCE` (yellow) when a fact's number
  does not appear in its cited source.
- **Citation family coverage**: every `*cite*` command is extracted (with
  optional arguments), unknown `*cite*` commands fail closed
  (`UNKNOWN_CITE_COMMAND`); bib entries need `arxiv`/`doi` (or `url` for
  `@misc/@online/@software/@dataset`) in a plausible format
  (`BAD_STABLE_ID_FORMAT`); missing keys are `MISSING_CITE` (red).
- **Exit-code contract**: `0` green, `1` red, `2` config/usage error, `3`
  yellow, `4` internal error. Nothing passes silently: missing config, empty
  facts, empty sections and missing bib are config errors with a reason.
- **Derived facts**: `derived_from` requires `expr`; evaluation is a whitelisted
  AST walk (no `eval`), arithmetic only; cycles and superseded-parent references
  are checked. `LEDGER_CONFLICT` / `DUPLICATE_VALUE` are yellow.
- **Recursive sections**: `sections/*.tex` also matches `sections/**/*.tex`, plus
  the `\input` closure; tex files outside the audit closure are reported
  (`UNSCANNED_TEX`).
- **Single lexical pipeline**: verbatim/`\verb` → comments (`\%` is not a
  comment) → command arguments → sub/superscripts (`R^2`, `x_{12}` are
  structural) → numbers. Normalisation: `1,234`=`1234`, `0.90`=`0.9`,
  `10\%`=`10%`, `1\,000\,000`=`1000000`; `value = "10/16"` accepts `10`, `16`,
  `0.625`.
- `--resolve` (opt-in): check arXiv/DOI online (5 s timeout); network failure is
  `CITE_UNVERIFIED` (yellow), a definite "does not exist" is `UNRESOLVED_CITE`
  (red).
- `matrix` and `preamble` subcommands; `--json` on every subcommand;
  `--strict` on `check`/`audit` to promote yellow to failure (for CI).
- Red-team fixtures `tests/fixtures/redteam-b1`, `redteam-b4`.
- `SPEC-V1.md` (29-item red-team verdicts, defence boundary §2.3),
  `IMPLEMENTATION-V1.md` (where each gate lives, known holes).

### Changed
- README rewritten for v1 (exit codes, manifest, preamble).
