# term-first-sentence｜首句给定义或可检验断言

## 治的判据

- 错误码：HEADING_ECHO
- 错误码：TERM_FIRST_IN_HEADING
- 现象：标题里的术语第一次出现时，本节首句没有给定义或可检验断言；
  或者首句只是把标题换个说法、加垫话、抛设问。

## 必做

1. 首句写成「属概念＋区别特征」的定义：X 是……的做法／机制／指标。
2. 或者写成可检验断言：给对象、条件、可测结果，读者能据此判断真假。
3. 定义句只讲这一件事，先不铺背景、不先讲重要性。
4. 首句必须引入标题里没有的新实义词。
5. 术语的别名第一次出现也按术语处理；同义词不算新信息。

## 禁做（含反例）

- 禁复述标题。反例：标题「预注册」，首句「预注册是预注册。」→ 零信息。
- 禁垫话。反例：`相关工作里，预注册很重要。` → 只表态，没有定义。
- 禁纯设问。反例：`什么是预注册？` → 把定义推给读者。
- 禁把定义留到第二段；首句不定义就不算首现解释。
- 禁用「效果很好」「非常重要」这类不可检验评价代替断言。

## 改写示例（旧 → 新）

| 旧 | 新 | 说明 |
|---|---|---|
| `本节讨论预注册。` | `预注册是在收集数据前固定假设与分析计划、并在见数据前留档的做法。` | 复述标题 → 定义 |
| `相关工作里，预注册很重要。` | `预注册要求在收集数据前冻结分析计划；十六次远程运行都按这份计划判卷。` | 垫话 → 可检验断言 |
| `什么是预注册？` | `预注册是……的做法；它把分析计划固定在见数据之前。` | 设问 → 定义 |

旧 → 新只改首句措辞，不改事实、数字与引用。

## 验收命令

```bash
env PYTHONPATH=src python3 -m factscribe prescribe term-first-sentence --json
```

改完把首句换进项目后再复核（占位符由人替换）：

```bash
env PYTHONPATH=src python3 -m factscribe style <项目> --diff <改前目录> --json
```
