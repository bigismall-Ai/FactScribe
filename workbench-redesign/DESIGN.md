## 一、旧界面四条病 → 新对策

旧 web 三栏工作台是 **editor-first**：编辑器在正中，人真正的高频动作（审账 / 签字 / 挑刺 / 定夺）全被挤到右栏附属位；AI 聊天常驻右栏混进 triage；没有「今日待办」总览与队列；mirror-check / refs / figures / bundle 四件新能力零界面。

| # | 旧病 | 新对策 | 原型里落在哪 |
|---|---|---|---|
| ① | **编辑器优先、任务靠边**——三栏结构的重心是写正文，审账/签字/挑刺/定夺这四种高频动作被降级成右栏附属 | **改成 task-first 的左栏导航**：左栏 8 组按「任务」分类而不是按「文件」分类；主区永远是一张张**动作卡**，不是编辑面。要写正文时，正文只是「挑刺 → 转实验题 → 回写」这条链上的一环，不再占据中枢 | 左栏 8 组导航；主区第一屏是「今日待办」队列卡流 |
| ② | **AI 聊天常驻右栏，混进 triage**——聊天与待判断的事混在同一视线里，人分不清「机器说」和「我要办」 | **AI 从 triage 面上撤走**：原型里没有任何常驻聊天面板；机器能做的只出候选（检索候选、复扫读数、建议口径），且**候选卡一律标「原型演示」**。每张卡的动作按钮是**人的动作**，AI 不代签 | 「检索候选」弹窗内标注「原型演示」；页脚写明 AI 不代签的边界 |
| ③ | **无「今日待办」总览与队列**——人打开工作台不知道「现在该干哪几件」 | **首屏就是今日待办队列**：按 5 类真实待办组排队，每卡＝类型徽章＋标题＋一句话＋**直接可点的动作按钮组**（不跳页）；j/k 上下移动、Enter 展开 | 今日待办 5 张卡；键盘流在待办队列与事实账表格上都生效 |
| ④ | **mirror-check / refs / figures / bundle 四件新能力零界面**——工具能跑，但没有让人用的面 | **一能力一视图**：8 组导航里各占一格（文献 / 双语 / 图表 / 交付），每格都是**真实读数驱动的**，不是空壳：文献是 7 条逐项登记表单，双语是 62 facts＋10 bib 零漂移卡，图表是空态＋三件套流程，交付是清单门五项过/豁免 | 导航第 4–7 组 |

## 三、参考了什么，各借了什么

- **Overleaf 审阅面板**——借「**问题挂在它出现的上下文旁边**」这一件事。挑刺卡不只给码和位置，还给**原文摘录**与**上下文展开**（H1 的 note 全文），审的人不用跳去文件里找那句话。同时借它「注释是行内对象、不是一个独立页面」的姿态：待办卡上直接放动作，不让人换页。
- **GitHub PR 检查队列**——借「**检查项是队列，队列项各有状态**」。顶栏徽章行＝PR 状态条（账本／黄牌／文献待办／双语／PDF）；交付页的清单门＝required checks（**过 / 不过 / 豁免**三态，过与豁免分开显示，不静默放行）；文献待办的 7 条＝待处理检查项队列，每条带具体缺什么字段。
- **Linear 键盘流**——借「**j/k 上下移动、Enter 展开**，视线不离开队列」。待办队列与事实账表格都支持 j/k/Enter；键盘移动时选中项高亮并滚动入视；输入框内不劫持按键。
- **额外借的**：**审阅台而非聊天窗**的形态——人类判断是一等公民，AI 产出降级为「候选 + 采纳（人签）」按钮；以及**每条事实一个「签名复核（人签）」按钮**——把「复核」做成逐条可点的动作，而不是一个全局开关。

## 四、交互原则清单

1. **每张待办卡上直接放处理动作，不跳页。** 处理就在卡内完成（弹层／就地展开），想跳过去看全貌时点「查看全部」是可选动作，不是必经之路。
2. **键盘流可用。** `j`/`k`（或 ↑/↓）在待办队列与事实账表格中上下移动，`Enter` 展开当前项；焦点在输入框时不劫持按键。
3. **所有写操作显式人签。** 按钮文案一律带「人签」字样（「签名复核（人签）」「补 authors（人签）」「登记（人签）」「确认是问题（人签）」「采纳（人签）」）。**AI 不代签**——页脚声明并给出仓库纪律出处：`fact add` 不改 `signed_by`/`[files]`（`factscribe/scaffold.py:8`）、检索候选入正式 `refs.bib` 必须人采（`factscribe/refs.py:22`）；相关裁定 **P-079**（2026-11-15 用户裁定，阴性）：「factscribe 有意『不判文字只判数』，AI 面板采纳写入不加 by-LLM/模型/采纳人痕迹，宿主模型不钉版本。」
4. **原型内所有「写」都是内存模拟。** 一律弹 toast「原型演示：正式版将写回账本」；原型不落盘、不改 `paper-b`。
5. **机器只出候选，标注清楚。** 模拟题录一律带「原型演示」标记；候选不自动进 `refs.bib`。
6. **数字带出处。** 页面上每个关键读数都能追到真读数来源（账文件行号、tool 输出路径、提交号），不出现无出处的概数。

## 六、已知边界（给审的人先说清）

- **原型只覆盖 paper-b 与姊妹盘 paper/ 的读数。** 工单里的 `results/MANIFEST.toml` 与 `h_conflicts` 实存于 `paper/`（及 `paper-zh/`）——`paper-b/` 下没有这两个文件；原型按真实路径标注，不假装它们在 paper-b。
- **「3 条缺字段 / 4 条待补登记」的切法**：3 条＝REFS-TODO 第 1、2 条（多智能体/端到端线）对应的 3 个 bib 条目 `paperorchestra2026`／`parness2026`／`aiscientistv2_2025`，三者都已 `\citep`（`sections/02_related.tex:10`）但 bib 无 `author` 字段；4 条＝第 3–6 条文献线（SciTeX-Clew／XScientist／工件评审＋W3C PROV／A-B 盲评与一致性）。第 7 条（预注册 `nosek2018preregistration`）字段齐、已引，页面上标为已办。
- **REFS-TODO.md 本身已滞后**：它说 7 条「提到但未 `\citep`」，实测 10 个 bib 键全部已被引用（audit `bib_unused` 为空）。原型按 bib 与正文实测显示「已进 bib／未登记」，不照抄 TODO 的旧状态。
- **`refs search` 的候选是模拟的**：正式版走 `factscribe refs search`（唯一联网面，候选落 `refs/candidates/` 并钉 sha256）；原型不联网，候选一律标「原型演示」。
- **`paper-b/` 未被写入**：本轮只读它；bundle 预演输出到 `/tmp` 下的临时目录。
