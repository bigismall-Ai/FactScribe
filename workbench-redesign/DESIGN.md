## 一、v1 为什么被否（用户原话与病根）

> 「不给人用的，人的逻辑和 LLM 逻辑完全不一样。」

病根不是配色也不是排版，是**把账本数据模型（码 / 路径 / token / 62 行表格）套皮当界面**。
v1 的首屏是「今日待办」队列卡流，左栏 8 组按**文件**分类，徽章行堆着「账本 62 条 · 全 high ｜ 黄牌 1 ｜ 文献待办 7 ｜ 双语一致 ｜ PDF 常设态 1」——
这是给工具看的一屏。审稿的人心里只有一件事：**读我的稿子**。v1 把这一件事挤到了一屏卡片的后面。

v2 的铁律一句话：**正文即主界面，机器视图退到角落。**
卷面上（正文与人话批注）不出现任何系统器官：码名、文件路径、toml 字段名、sha 十六进制，全部只允许出现在抽屉里。

## 二、v1 → v2 对比

| 维度 | v1（被否） | v2（本次） | 为什么这么改 |
|---|---|---|---|
| **首屏是什么** | 今日待办队列（5 张动作卡） | 封面卡 + 论文正文第一段 | 人打开稿子是为了读稿子，不是为了领任务 |
| **主体形态** | 8 组导航 ＋ 8 个视图（事实账 62 行表／挑刺／文献／双语／图表／交付／报告） | **一列连续正文**，8 节按编号全渲染，无跳转 | 连续阅读是长文的正确形态，视图切换会打断语义链 |
| **批注的位置** | 独立的「挑刺」视图，带码／位置／原文摘录 | **长在段落旁**：段后横排卡 或 右侧边注（窄屏自动落段下） | 批注必须带着它批评的那句话出现，人不用跳回去找 |
| **机器数据的位置** | 主区就是 62 行账本表、路径、sha | **收进抽屉**（账本／黄牌／文献登记／索引四页），默认关 | 机器字段是给人核的，不是给人读的 |
| **顶栏** | 5 枚计数徽章堆砌 | **三句人话**：「数据全有据可查 ✓」「1 条小提醒」「文献欠 3 篇作者名」 | 徽章堆是 LLM 的信息密度偏好；人只关心三件事：能不能信、有没有刺、欠什么 |
| **节标题** | 英文原名 | 中文人话标题 ＋ 英文副标题（如「二、别人做过什么，我们差在哪 / Related Work」） | 目录是人话，不是文件名 |
| **事实标记** | 表格里的 id 列 | 正文里小 ✓ ＋ 虚线下划线，**悬浮出小卡**：账本值／说法／出处／指纹已核 | 数字在正文里保持干净，出处随鼠标来 |
| **写作** | 表单＋按钮（隐含可写） | **只读**：页脚明说改稿回惯用工具 | v2 的职责是把「哪里要看一眼」指出来，不是替人改稿 |
| **结尾** | 无 | 「全文读完 ✓ 2 类批注待处理」 | 读完要有收口 |

**参考仍沿用 v1 借来的三件**：Overleaf 的「问题挂在它出现的上下文旁边」、GitHub PR 的「检查项即队列、状态即读数」、Linear 的「处理就在原地完成」。
**v2 新增的一条**：正文流优先于任何列表——列表可以收进抽屉，正文不行。

## 五、与工单的两处偏差（如实说明）

1. **成本口径提醒的宿主段落不在论文 B 里面。**
   工单把 `facts/d_cost.toml` 的 D1/H1 记在论文 B 名下；实测：`paper-b/facts/` 下**没有** `d_cost.toml`，62 条账里**没有** D1/H1 两个 id，论文 B 的正文也**没有任何成本段**（grep `cost-per-task`／`1.66`／`3×` 全部零命中）。
   D1／H1 实际住在**姊妹盘论文 A**（`paper/facts/d_cost.toml`，正文在 `paper/sections/01_intro.tex`、`05_eval.tex`）。
   v2 的处理：正文仍按工单渲染论文 B 的 8 节；这条提醒挂在第二节 Position 段（「…the rest of the paper is an account of what it costs」）旁——那是本篇唯一谈到成本的句子；批注里引姊妹稿原文，并明说「这段出自姊妹稿的成本一节，不在本篇正文里」，不假装它属于本篇。抽屉「黄牌」页保留了它的真实机器字段（指标／口径／两条账／位置／exit=3）。

2. **缺作者的是 5 条，不是 3 条。**
   工单与顶栏文案按「3 篇」写（PaperOrchestra／PARNESS／AI Scientist-v2，均在 `02_related.tex:10` 同一处 `\citep` 里，已跟踪的文献线①）。
   实测 `refs.bib` 10 条里 **5 条**没有 `author` 字段，另两条 XScientist 2026、SciTeX-Clew 2026 属文献线②（待补登记线）。
   v2 的处理：顶栏按工单口径写「文献欠 3 篇作者名」；正文对 5 处**都**标琥珀色 `[缺作者]`（漏标＝撒谎）；其中 3 条各挂一张卡（按工单的 `[补作者] [忽略]`），另 2 条合并成一张卡并说明「属另一条还没登记的文献线，缺的是同一样东西」。

**另有一条 v1 记录的边界已过期**：v1 写过「FACTS-B 索引滞后（S3a/S3b/S3c 记成 med，账本 TOML 是 high）」——`FACTS-B.md` 已于 11-18 13:53 重新生成，实测三条均已记为 `high`，与账本一致，索引漂移已消失。v2 抽屉按新状态呈现。

## 六、已知边界

- **原型不写任何东西。** 所有「补作者／知道了」都是内存模拟，只弹 toast；正式版会写回文献登记表。
- **只读论文 B 与姊妹盘论文 A**，本轮未写入任何一个目录。
- **`refs search` 的候选仍是模拟的**（v1 遗留说明）：正式版走 `factscribe refs search`，候选落 `refs/candidates/` 并钉 sha256；原型不联网。
- **`\fact` 在正文里渲染成小 ✓ 而不是账本值本身**：`main.tex` 的注释写明「`\fact{ID}` 只做审计绑定，排版不产生字符」。若把账本值直接插进正文，会出现「reached 11/12 11/12（首跑，#7）」这种重复；故正文保持干净，账本真值放在悬浮小卡里（「有据：账本值／说法／出处／指纹已核」）。
- **抽屉里的路径与 sha 是有意的**：那一层就是机器视图，工件级细节只在这里出现。

## 八、v2.1：编辑与 AI 抽屉（本轮新增）

### 8.1 为什么要加这两件

v2 的职责边界写得很清楚：**只负责把「哪里需要你看一眼」指出来**，改稿回你惯用的编辑器。
这一轮（P-158）暴露了两个断点：

1. **指出来之后要换台机器改。** 看见「这条引用缺作者」，得切回编辑器找到那句、改完、再切回来核一遍。
2. **AI 没有位置站。** 想问一句「这段为什么被标了缺作者」，只能另开窗口；AI 的话也没有落点。

所以 v2.1 加的**不是编辑器**，是**把动作留在原地的那一层**：改写就地发生，出处就地可见，
AI 就地给建议、就地采纳。v2 的四件东西——正文中心、人话批注、机器视图抽屉、顶栏三句人话——一件没动。

### 8.2 段落即点即编：受保护芯片（核心）

**交互**：正文每一段（88 段，各带一个稳定 id `p1…p88`）悬停即在右上角浮出两个按钮：
`[编辑]` `[问 AI]`。点 `[编辑]` 进入编辑态，段落下挂一条动作条：

```
[🔒 受保护芯片：散文可以直接改；引用与数据渲染成芯片（灰＝引用，蓝＝数据），改字删不掉它们…]
                                                    [保存（人签·写回演示）] [取消]
```

**芯片的两种脸**：

| 源命令 | 编辑态渲染 | 颜色 | 悬浮小卡给什么 |
|---|---|---|---|
| `\citep{key}` | （作者, 年）；作者缺失时是（[缺作者], 年） | 灰底（缺作者为琥珀底） | 文献键／题名／作者／年／出处 |
| `\fact{ID}` | 账本值本身（如 `30/36（83%）`、`0/36（valid 误红）`） | 蓝底 | 账本值／说法／出处（人类可读）／定位／指纹已核 |

**这是 factscribe 工作台编辑的差异化设计**：编辑态把散文与「有据的东西」分成两种视觉实体，
所以**改文字不可能误删数据与引用**。读态正文仍然是干净的（小 ✓ + 悬浮小卡），
账本值只在编辑态才展开——不展开就会重复出「reached 11/12 11/12（首跑，#7）」这种脏句。

**保护机制（三层，原型级）**：

1. `contenteditable=false` 的 inline 芯片：芯片本身不可进入编辑。
2. `beforeinput` 拦截：任何会碰到芯片的删除操作在执行前被拦下——
   - 光标紧贴芯片按退格 → 整步不放行（这一步浏览器本来会删掉芯片）；
   - 跨着芯片整段选删 → **散文照删，芯片按快照原样留在原处**（芯片用进入编辑态时的快照重建，
     所以不会出现「删了一半的芯片」）。
3. `input` 兜底：若仍有芯片从 DOM 消失，按左右文锚点把它插回原位并弹提示。

实测（Chrome，1440×940）：

| 操作 | 结果 |
|---|---|
| 光标贴着芯片按退格 | 芯片数不变，弹「🔒 受保护：这一处有引用／数据芯片，删不掉」 |
| 全选整段（含芯片）按退格 | 散文全删，**2 个芯片原样留下**（顺序不变、内容不残缺） |
| 只删不含芯片的散文 | 正常删除，芯片不受影响 |
| 保存 | 芯片还原成读态元素（`\citep` → `.cite`、`\fact` → `.fc`），段落打上「改」记号 |

**保存**：内存更新 ＋ 重渲染 ＋ toast
「原型演示：正式版将写回 sections/*.tex，命令 token 保护」。
正式版里写回的是 `.tex`，`\citep`／`\fact` 作为**命令 token 原样保留**——
人改的是散文，token 由闸守着，这就是「命令 token 保护」的意思。

### 8.3 agent 沟通抽屉

右缘悬浮按钮「问 AI」→ 右侧抽屉（可收起，Esc 也关）。抽屉顶部一句边界声明：
**「AI 只建议，采纳才生效（人签）」**。内置三个 canned 能力（原型内模拟 agent，不联网、不调模型）：

| 能力 | 回答形态 | 数据来源 |
|---|---|---|
| ① 总结这篇论文的状态 | 人话摘要：62 条数据全有据／5 处引用缺作者／双语零漂移／要你动手的与别误改的 | 账本 62 条（置信全 high，全带 source+sha+locator）；bib 10 条里 5 条无 author；`factscribe mirror-check paper-b paper-b-zh` 实跑 exit=0、drift 0 |
| ② 对某段提修改建议 | 建议卡：现状句／建议句／理由 ＋ `[采纳（人签）]` `[忽略]` | 三条手写建议，锚句逐字取自渲染后正文；生成器对不上锚句会直接报错（不许带病上线） |
| ③ 这段为什么被标了缺作者 | 解释卡：文献键／题名／年／「refs.bib 里这一条没有 author」 | `refs.bib` 逐条实查 |

- **采纳** → 该段按建议句更新（内存）＋ 重渲染 ＋ toast「已按建议改写（人签）」，段尾打「AI 采纳」记号；
  段里的引用／数据芯片**原样保留**。
- **忽略** → 卡片转灰记「已忽略（只记录）」，不改稿。
- **联动**：从段落 hover 的 `[问 AI]` 入口打开抽屉，抽屉自动带上该段（所属节、原文摘录、该段的引用/数据计数）；
  此时问「这段为什么被标了缺作者」会针对**这一段**的那一条缺作者引用作答。
- 抽屉打开时正文列自动让位（不遮住段落的悬浮按钮）；与机器视图抽屉互斥（开一个关另一个）。

### 8.5 v2.1 的已知边界（如实说明）

- **原型仍然不写任何文件。** 「保存」「采纳」只改内存里的这一份稿子；正式版才写回 `sections/*.tex`。
- **保护机制是原型级的**：靠 `contenteditable=false` ＋ 拦截 ＋ 还原实现；
  正式版的「命令 token 保护」是另一套（在 `.tex` 层面保住 `\citep`／`\fact` token），不是同一件事。
- **不支持在段内新建芯片**：原型只支持纯文本改写（含增删词句）。
  新建引用／新建数据仍走正式版（改 `refs.bib`／`facts/*.toml` 并重挂 `\citep`／`\fact`）。
- **AI 是模拟的**：三个 canned 能力，无模型调用、无联网；建议句是手写的三条，不是模型生成的。
- **只读论文 B 与姊妹盘论文 A**，本轮未写入任何一个目录。

## 九、v2.2：中英版本切换器（整份换盘渲染）

> **本件 v2.2**：在 v2.1 上加一件——**顶栏「英文版｜中文版」分段切换器**。
> 产出物 `prototype-v2.2.html`（单文件、离线零外链、真实双盘数据）；**v2.1 文件原样保留**（`prototype-v2.1.html` 未删未改）。

### 9.1 切换＝换盘，不是换语言

切换钮摆的不是一个字符串，而是一个**数据源指针**。按下「中文版」时：

| 换盘的东西 | 英文版（默认） | 中文版 |
|---|---|---|
| 正文 | `paper-b/sections/*.tex` 逐节渲染 | `paper-b-zh/sections/*.tex` 逐节渲染 |
| 节目录 | 中文人话名 ＋ 英文副名（八节） | 中文人话名取自 zh 盘的 `\section{}`，副名沿用英文盘 |
| 封面 | `paper-b/main.tex` 的题名与副题 | `paper-b-zh/main.tex` 的题名与副题 |
| 批注 | 缺作者 ×5 ＋ 成本口径 ×1 | 缺作者 ×5 ＋ 成本口径 ×1（见 9.3 跟盘规则） |
| 待办（文末读数） | 「2 类批注待处理」 | 「2 类批注待处理」（按当前盘实时算） |
| 引文集合（抽屉「文献登记」的「正文已引」列） | 英文盘正文引到的键 | 中文盘正文引到的键 |

两盘正文用**同一个渲染器**生成（`gen_v2_2.py` 直接复用 `gen_v2_1.py` 的
`Renderer` / `render_section` / `assign_pids`），不是手工另写一套中文模板。
英文盘渲染结果与 `prototype-v2.1.html` 的正文**逐字相同**（自检里给了比对方法）。

### 9.2 双语对账状态行（常驻）

切换钮旁一小行：

> **双语对账：一致（62 facts＋10 bib，2026-11-18 实测 drift 0）**

这行字的**真值来源是实跑**：

```
factscribe mirror-check /Users/moc/workspaces/SiAgent/paper-b \
                        /Users/moc/workspaces/SiAgent/paper-b-zh --json
```

实跑输出（exit=0，status=ok）：`facts_a=62, facts_b=62, bib_a=10, bib_b=10, drift_count=0`。
整份 JSON 原样烘进原型（`RECON.truth`），文案由它生成，不是手写的。

**漂移警示形态**：行尾一个「预置漂移演示」按钮，点一下这行变成警示色与警示文案，
但**真值一个字节都不改**——警示形态里明写「预置演示形态，非实测」并复述真读数
（`真值仍是 62 facts＋10 bib，drift 0`）。再点一下还原实测读数。

### 9.3 批注跟盘规则（三条，逐条落到盘上）

| 批注 | 英文盘 | 中文盘 | 依据 |
|---|---|---|---|
| **缺作者引用**（×5） | 挂 | 挂（同现） | `paper-b/refs.bib` 与 `paper-b-zh/refs.bib` **逐字一致**（md5 `f44b880c…`），10 条里同样 5 条无 `author` 字段；两盘正文的 `\citep` 键集合也完全相同（10 键） |
| **成本口径提醒**（×1） | 挂 Position 段 | 挂「定位」段 | 按节结构映射。中文盘 grep 成本相关句**有命中**：`02_related.tex:19` 的「后文记录的，是为此付出的代价。」——与英文盘 `02_related.tex:60` 的「…an account of what it costs.」是同一句的中译，故挂；若 grep 不到则中文盘不挂并在此注明 |
| **工程类批注**（AI 修改建议卡 ×3） | 挂 | **不挂**（zh 盘从简） | 三张建议卡的锚句逐字取自英文正文（如「A planner turns a topic or a result set into a section structure…」），中文盘没有这句话，卡挂不上。中文盘问「这段有什么可改的？」时明说：本轮建议卡只挂英文盘，中文盘从简 |

**已知的一处口径沿袭**（不是 v2.2 引入的，v2.1 就这样）：`\begin{abstract}` 的正文被渲染到
摘要框**外面**（框里只剩「摘要」两字）。两盘表现一致——因为是同一个渲染器。
本轮**没有**修它：修了英文盘正文就不再与 v2.1 逐字相同，与「零改动保留」冲突。正式版应修渲染器。

### 9.4 中文盘排版（按中文阅读习惯微调）

| 维度 | 英文盘 | 中文盘 | 理由 |
|---|---|---|---|
| 行宽（`.page` max-width） | 700px | **620px** | 620px ÷ 16px ≈ **38 个全角字／行**，落在中文正文 30–40 字的舒适区 |
| 字号（正文 `p`） | 16.5px | **16px** | 全角字面宽是西文的两倍，字号略收，行宽才守得住 |
| 行高 | 1.92 | **2.02**（实测 32.32px） | 中文没有词间空格，行高略宽才不粘连 |
| 段距（`p` 下边距） | 1.15em | **1.35em** | 中文段落靠缩进与间距分隔，段距要留够 |
| 对齐 | `left` | `justify` + `inter-ideograph` | 中文两端对齐是常规做法，避免标点悬挂 |
| 字距 | — | `letter-spacing:.015em` | 补偿全角字面的视觉松散 |

### 9.6 v2.2 的已知边界（如实说明）

- **原型仍然不写任何文件。** 切换只是换内存里的数据源；「保存」「采纳」只改当前盘这一份稿子。

  （`DISKS` 数据、`renderDisk()`、切换器与对账状态行）；v2.1 的 JS 常量
  （`CITED` / `PARA_META` / `SUG` / `ORIG_HTML`）从 `const` 改成随盘刷新的 `let`。

- **对账状态行只读**：原型不跑 mirror-check，预警形态是预置的演示形态。
