# section-completeness｜每节首段交代任务与结论

## 治的判据

- 错误码：SECTION_INCOMPLETE
- 现象：本节首段只交代「要讨论什么」，没有给出本节结论；结论写成
  不可检验的评价，或用「详见下文」推后。
- 检查点转述自 XtraGPT 的 20 条学术写作标准里与章节组织相关的项
  （用自己的话写，不抄原文措辞）。

## 必做

首段至少两句话，各管一件事：

1. 任务句：本节做什么（比较什么、给出什么、验证什么）。
2. 结论句：本节结论是什么，落到「对象＋条件＋结果」，读者能复述。
3. 段内顺序：任务 → 方法／证据 → 结论；不先铺三段背景。
4. 本节是过渡节时，明说「本节只交代 X，结论留给 Y 节」。
5. 一节只承担一个论证任务；新任务另起一节。

检查点（转述 XtraGPT）：

- 首段有任务句与结论句；
- 结论可复述、可检验，有对象与条件；
- 首段不重复上一节结论，也不复述标题；
- 节末不引入新任务。

## 禁做（含反例）

- 禁只写任务不写结论。反例：`本节讨论提示词对机制的影响。` →
  读者不知道结论是什么。
- 禁空泛评价代替结论。反例：`提示词对机制非常重要。` →
  没有对象、条件与结果。
- 禁用「详见下文」「后文会说明」把结论推后。
- 禁首段先铺三段背景再进任务。
- 禁一节塞两个新任务。

## 改写示例（旧 → 新）

| 旧 | 新 | 说明 |
|---|---|---|
| `本节讨论提示词对机制的影响。` | `本节比较提示词与机制在十六次运行中的差异。结论是：机制改动带来的读数变化大于提示词改动。` | 任务句 ＋ 可检验结论 |
| `提示词对机制非常重要。` | `本节给出提示词与机制在十六次运行中的对照；机制组的读数变化更大。` | 空泛评价 → 对象＋条件＋结果 |

旧 → 新只补首段，不动后面的证据与数字。

## 验收命令

```bash
env PYTHONPATH=src python3 -m factscribe prescribe section-completeness --json
```

改完把首段换进项目后再复核（占位符由人替换）：

```bash
env PYTHONPATH=src python3 -m factscribe style <项目> --diff <改前目录> --json
```
