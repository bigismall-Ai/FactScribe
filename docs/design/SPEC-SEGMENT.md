# SPEC-SEGMENT｜中文分词底座与 `ZH_LIGHT_VERB_NOUN`（批 104）

状态：批 104 定稿。分词器只服务 `style` 的中文判据，不进 `audit` 的
数字/引用链路，不改变既有退出码（仍是 0 / 3）。词表来源与许可见
`factscribe/terms/SOURCES.md`；实现读数见 `docs/implementation/SEGMENT.md`。

## 0. 为什么要先有分词

`ZH_LIGHT_VERB_NOUN` 要判断「进行／作出／加以／给予／予以 ＋（的）＋
名词」里的名词，靠字符正则做不到：同一个字串在别的句法位置可能是动词
（`进行分析` 的名词 vs `分析数据` 的动词）。词性只在词表里，所以先落地
一个纯标准库、可复现、带词性的中文分词器，再让判据消费 token 的词性。

此前不可实现的原因：没有分词就没有词性；用 `n` 字面匹配会把 `进行`
本身、`的`、标点都当成候选，四份语料会大面积误报。

## 2. 分词器（`factscribe/segment.py`）

### 2.1 算法

正向扫描＋最大概率切分，单次匹配长度上限 **10 字**：

1. 从左到右扫描；遇到中文段才查词表，非中文（英文、数字、标点、空白）
   连续成块原样保留，词性为空。
2. 每个中文段建一张有向无环图：位置 `k` 的边是词表里所有
   `text[k:k+L]`（`L = 1…min(10, 段末)`），边的分数是
   `log(词频 / 词表总词频)`；未登录字只有 `L=1` 的边，分数固定为
   `log(1 / 词表总词频)`。
3. 从段末向前取分数和最高的路径；同分时取**较长**的候选，再同长取
   **词频较高**者。一个词表候选都没有时，按单字切出（未登录字）。
4. 路径就是该中文段的切分；token 带词性。

为什么不是「逐位按词频贪心」：词频最高的往往是单字（`南 / 京 / 市`
分别比 `南京市` 高），逐位贪心会把 `南京市长江大桥` 切成单字串。
为什么不是「逐位取最长」：`研究生命起源` 会被切成 `研究生 / 命 / 起源`。
整段对数词频和同时避开这两种退化，并让两个验收歧义例都得到自然切分：

| 输入 | 输出 |
|---|---|
| `研究生命起源` | `研究 / 生命 / 起源`（不是 `研究生 / 命 / 起源`） |
| `南京市长江大桥` | `南京市 / 长江大桥`（不是 `南京 / 市长 / 江 / 大桥`） |

没有随机数、没有哈希遍历、没有文件系统顺序依赖；同一输入在同一词表上
输出恒定。

### 2.2 接口

```python
segment(text) -> list[(token, start, end, pos)]
load(path=None) -> dict[str, tuple[int, str]]   # 惰性加载，进程内缓存
```

- `start` / `end` 是相对输入串的字符下标，`text[start:end] == token`；
- `pos` 取词表第三列；未登录字与非中文块为 `""`；
- `load()` 默认读包内 `terms/seg.tsv.gz`，显式 `path` 可换词表；同一路径
  第二次调用直接返回缓存；
- 正则词表行格式错（列数不对、词频不是整数）按配置错误抛出，不静默跳过。

### 2.3 词性口径

判据里的「名词」＝词性以 `n` 开头（`n / nr / ns / nt / nz / nrt` 等），
**外加 `vn`（动名词）**。原因：结巴把 `分析 / 研究 / 评估 / 调整 / 优化`
这类高频动名词标成 `vn` 而不是 `n`；只认 `n` 会让验收例句
`进行了分析` 永远报不出来。`vn` 是有名词性的动词，仍符合「动作藏在
名词里」的判据；纯动词 `v`（`说明 / 讨论 / 支持`）不报。

## 3. 判据 `ZH_LIGHT_VERB_NOUN`（黄，按条报）

### 3.1 形态

```
(进行|作出|加以|给予|予以) + 可选体标记(了|着|过) + 可选「的」 + 名词
```

- 名词必须紧跟在光杆动词/体标记/「的」之后，中间夹数量词、形容词、
  副词都不报（精度优先；`进行了三次测试` 不报）；
- 名词后面紧跟另一个名词/动词时，视它为修饰语、不报（`进行了专门优化`
  里的「专门」被结巴标成 `n`，但中心词是「优化」；不报修饰语）；
- 同一句出现几处报几处，**不设密度闸**；
- 只出黄牌，`style` 退出码仍为 3；不改正文、不改 `audit`。

### 3.2 报告内容

每条必须给出「动作其实是什么」：

- `进行了分析` → `分析了`；
- `对方案进行了调整` → `调整了方案`（或直接 `改方案` 的人话版）；
- 词表里没有对应动词时，提示删掉轻动词、让名词直接作谓语。

动作查表在 `style-rules.toml` 的 `[zh_light_verb_noun.actions]`；查不到时
给通用改法，不猜同义词。

### 3.3 白名单（正常搭配，不报）

配置在 `style-rules.toml` 的 `[zh_light_verb_noun].exempt_phrases`：

- `进行中`、`进行时`（「正在进行中」「会议进行时」是状态/时间，不是动作）；
- `作出决定`（既定搭配，且 `决定` 在结巴里是 `v`，本就不会命中；仍写进
  白名单，防止换词表后回归）。

白名单按「光杆动词到名词」的整段原文精确匹配。新增项必须写进配置、
在测试里留反例，不许写死在代码里。

### 3.4 单位与反向锁

- 单位：**条**（每出现一处算一条），不是每千字密度；
- 反向锁：英文语料 `paper`、`paper-b` 以及不含轻动词的中文句必须
  **0 触发**；测试里用英文句和「讨论仍在进行。」固定住。
